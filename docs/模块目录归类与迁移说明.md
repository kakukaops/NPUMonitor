# 模块目录归类与迁移说明

日期：2026-11-11。范围：仓库内资产归属和引用迁移，不改变GPU规则判据或新增ML业务能力。

后续GPU/NPU目录演进见[异构加速器监控目录规划](异构加速器监控目录规划.md)。本文保留第一轮迁移事实。后续物理迁移已执行，当前路径和验收见[异构加速器目录迁移与验收](异构加速器目录迁移与验收.md)。

## 1. 归类结果

```text
modules/
├── gpu-monitoring-rules/     # 原GPU规则文档、代码、模拟器、测试和证据
├── gpu-monitoring-ml/        # GPU ML设计、通用时序ML原型及其证据
├── gpu-monitoring-common/    # 共用指标、硬件、来源和输入契约
└── layout-migration.json     # 旧文件到新文件的映射及冻结内容摘要

deploy/                      # 跨模块整体编排
docs/                       # 跨模块方案与本说明
scripts/                     # 完整性检查和旧命令转发
.local/                      # 原凭据、临时结果，不移动、不提交
```

原有278个文件迁移到对应模块。规则专项01～10文档在规则模块docs；通用ML方案和插件化备选仍在根docs；原GPU研究报告和笔记在规则模块，ML调研和笔记在ML模块。

公共模块保持轻量，只抽取已有确定共用的指标和硬件契约；现有规则代码先保留归属，不提前抽成新的通用SDK。

## 2. 唯一事实源与兼容方式

公共资产只有一个实体文件。规则模块monitoring内有10个相对符号链接用于旧生成器的读取视图：hardware、metrics、指标台账、指标模板和6份共用catalog文件。它们不是第二份配置，也不是根目录旧路径的全量别名。复制或打包模块时必须保留公共模块依赖。

根目录只保留三个旧命令转发：

```bash
bash scripts/lab.sh ...
bash scripts/test_monitoring.sh
bash scripts/anomaly-demo.sh ...
```

实现和新文档命令均位于各模块scripts下。其他旧Python/JS工具使用新路径，没有保留根目录副本。

## 3. 运行兼容

共享Compose文件仍在deploy目录。宿主机代码、规则和ML构建上下文改为模块内路径；容器内/app、/rules等约定、端口、服务名、Compose项目名及命名卷保持原值。

现有凭据和临时结果仍位于根.local。迁移不删除数据库或卷，不重新初始化已有业务组和规则，不执行全量规则导入。已启动的绑定挂载源路径通过受影响服务的重建更新；数据库和共享Prometheus/夜莺本体不因纯代码归类而重建。

## 4. 文档、生成器与证据

Markdown引用按新实体路径重定位，常用命令改为模块入口；生成器在每次渲染时执行同样的路径转换，防止重新生成后出现旧链接。

既有非Markdown规则配置、输入契约、Prometheus测试fixture、JSON/YAML/TXT验收载荷保持原字节和SHA256。冻结历史记录中的原路径是记录时的相对路径，使用layout-migration.json定位，不为更新路径而改写历史证据内容。可维护的Markdown导航不属于冻结载荷。

- 旧 `scripts/lab.sh verify` 入口通过；九个服务healthy、六个Prometheus目标up，受影响容器已使用模块内挂载。
- 夜莺、Prometheus、端口、项目名和命名卷保留，未执行规则重新导入、数据库初始化或故障场景全量重放。
