# 异构加速器目录迁移与验收

日期：2026-11-12。监控包装版本：0.5.1。范围为目录落地及公共能力提取，不新增NPU采集或检测效果。

## 1. 当前目录

```text
modules/
├── platform/
│   ├── integrations/                 # 公共Prometheus/夜莺HTTP集成
│   └── ml-monitoring/backend/        # 公共SQLite元数据/结果/状态存储
├── model-services/
│   ├── contracts/                    # 统一模型平台协议
│   ├── adapters/                     # HTTP适配器，公司平台扩展位置
│   ├── runtime/                      # 通用数值流水线、检测器及评估
│   └── reference-platform/           # 独立训练/部署/推理服务
├── devices/
│   ├── nvidia-gpu/
│   │   ├── common/                   # 既有NVIDIA指标、硬件和来源
│   │   ├── adapters/                 # NVIDIA算法与兼容扩展
│   │   ├── rules/                    # 既有规则实现和验收
│   │   └── ml/                       # GPU场景、Web/API、编排、设备扩展
│   └── huawei-npu/                   # 开发说明和接入边界，暂无业务实现
├── gpu-monitoring-rules/scripts/     # 旧Shell命令薄包装
├── gpu-monitoring-ml/scripts/        # 旧Shell命令薄包装
└── layout-migration.json             # 历史路径追溯

deploy/
├── shared/                          # Redis、夜莺、Prometheus共享定义
├── nvidia-gpu/{lab,review,ml}/       # GPU运行组合与采集配置
└── model-platform/                  # 独立参考模型平台定义
```

公共层是实际提取的代码，不复制GPU实现另建同名平台。当前GPU页面、场景和编排仍含设备语义，保留在NVIDIA包；NPU接入时再按真实输入契约提取共用Web与编排。目标规划中的完整公共Web/API、设备身份契约和动态注册界面尚未实现。

## 2. 模型与设备边界

DCGM条件检测及残差漂移实现位于 `modules/devices/nvidia-gpu/adapters/nvidia_gpu_ml/`。通用runtime不再导入GPU settings或DCGM扩展，通过显式schema和安装注册表运行。参考平台通过 `MODEL_DEVICE_PLUGINS=nvidia_gpu_ml.plugin` 加载已安装的NVIDIA扩展，不加载监控引擎、时序查询或夜莺代码。

旧 `gpu_ml`、`gpu_ml_runtime` Python名字保留兼容入口，以便现有joblib权重继续加载；GPU历史模型实体位于设备包。保留这些名字不表示通用算法仍内置DCGM字段，也不将GPU权重视作NPU可用权重。公司平台协议和HTTP适配器有唯一实体实现，GPU旧导入路径仅作兼容。

## 3. 运维兼容

原根Shell命令、原GPU模块的常用Shell入口保留薄包装。其他Python工具与文档使用新路径；未建立整棵目录软链，避免出现两个源码位置。规则模块原有10个共用视图仍指向唯一NVIDIA common资产。

Compose项目名、服务名、端口、数据卷名、凭据位置及夜莺对象归属不变。GPU组合通过extends复用基础组件和模型平台定义；Prometheus的GPU实验采集配置仍归GPU部署。`deploy/shared/compose.yaml`已可独立解析，但不能与GPU组合并行以同一项目重复管理组件。

本次不删除卷、不执行数据库初始化、不重导入规则、不重新发布模型。源码和配置绑定路径改变的服务需要重建，以加载新挂载；现有ML两个服务使用0.5.1镜像。根 `.dockerignore` 排除私有凭据及本地数据，根构建上下文仅COPY所需模块。

[迁移登记](../modules/layout-migration.json)保留首轮与本轮旧文件映射。45份原冻结非Markdown规则/契约/证据保持字节摘要。旧v5等证据仍代表当时源码，不能当作0.5.1当前源码摘要；本轮验证单独记账。

## 4. 验证入口

```bash
python scripts/check_module_layout.py
python modules/devices/nvidia-gpu/rules/scripts/check_monitoring.py
python modules/devices/nvidia-gpu/rules/scripts/check_h100_training.py
python modules/devices/nvidia-gpu/rules/scripts/render_h100_inventory.py --check
bash modules/devices/nvidia-gpu/rules/scripts/test_monitoring.sh
bash modules/devices/nvidia-gpu/rules/scripts/lab.sh test
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh test

```

`scripts/verify_accelerator_layout.py capture/verify <本地快照>`只读比较迁移前后任务、模型引用、平台身份、完整夜莺规则与数据卷，不输出凭据。完整性检查增加公共代码厂商导入隔离检查。独立模型测试增加无设备扩展的实际训练/评分/存取验证和监控控制面缺席验证。

## 5. 验证结果

- 696条历史路径登记有效，45份冻结载荷摘要未变，10个公共视图及21处绑定源有效。
- 规则行为27项、GPU ML39项、模型平台8项，共74项Python测试通过；6组PromQL测试351用例、830断言通过。
- 5个Compose配置可解析，11个现有服务运行并健康；旧Shell入口验证通过。
- 21个任务、34个模型引用、86条完整夜莺规则及原数据卷/平台身份与迁移前一致。
- 30个历史本地模型加载成功，现有API部署评分成功，共享Prometheus及夜莺传输实际只读调用成功。
- 7个页面DOM数据契约通过；未执行真实浏览器视觉/点击验收。

最终结果记录在 [本轮验收证据](../modules/platform/evidence/heterogeneous-layout/summary.json)。不改变真实GPU、真实NPU、真实公司平台与生产HA的未验收状态。
