# Huawei Ascend NPU监控开发入口

状态：规划/待采集验证；没有实现NPU采集、规则、ML场景或生产验收。不得用GPU测试记录证明NPU能力。

## 后续模块归属

| 子目录 | 开发内容 |
|---|---|
| `common/` | NPU型号范围、采集字段、单位/类型、有效值、来源、支持能力矩阵 |
| `adapters/` | 实际采集器适配、节点/物理设备/逻辑设备身份映射 |
| `rules/` | NPU规则判据、查询、恢复证据、处置与独立测试 |
| `ml/` | NPU特征schema、检测场景、模型绑定和独立验收 |

相应目录在产生实际实现时建立。共用 [平台集成与存储](../../platform/README.md) 及 [模型服务](../../model-services/README.md)，不复制GPU完整后端、前端或训练平台。

## 开发顺序

1. 收集现场设备型号、形态、固件/CANN、采集器及版本、真实Prometheus样本与标签；核实稳定身份和逻辑设备关系。
2. 建立指标台账，明确可用、缺失、非法、陈旧及不支持的状态；指标同名或用途接近不代表与DCGM语义相同。
3. 完成只读采集、查询和身份验证，再分别开发规则与ML场景。仅使用现场实际存在的输入，不假设具有上层作业信息。
4. 使用独立测试与命名空间验收；GPU模型不能直接用于NPU，需按特征契约重新训练和验证。

共享界面与设备注册加载在接入阶段实现；本次不虚构NPU指标名称、阈值、模型效果或硬件故障测试。
