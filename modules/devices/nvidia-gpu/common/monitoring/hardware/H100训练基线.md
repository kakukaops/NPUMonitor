# H100训练场景与驱动基线

日期：2026-11-06；baseline_id：h100-training-r595-20261106。  
结构化记录：[driver-baseline.yaml](../catalog/driver-baseline.yaml)

## 1. 已确认范围

用户确认H100用于训练，不启用虚拟化。第一版以物理GPU监控为目标，不建设vGPU、虚拟机直通或hypervisor专用规则。容器化训练并不自动等于GPU虚拟化，是否使用容器/Kubernetes不作额外推断。

MIG模式独立记录，不从“无虚拟化”推导MIG已关闭；第一版仍不纳入MIG实例级规则。PCIe/SXM/NVL、实际互联拓扑、软件栈和采集配置继续作为待核实项。

## 2. 生产驱动选择

截至2026-11-06，NVIDIA支持矩阵将R595标为Production Branch，release元数据中该分支最新Linux版本为595.112.07，发布日期2026-10-22。第一版采用该确切版本作为Linux设计参考，不使用浮动latest标签。

来源：[官方分支支持矩阵](https://docs.nvidia.com/datacenter/tesla/drivers/supported-drivers-and-cuda-toolkit-versions.html)、[官方release元数据](https://docs.nvidia.com/datacenter/tesla/drivers/releases.json)、[固定595.112.07发行说明](https://docs.nvidia.com/datacenter/tesla/tesla-release-notes-595-112-07/index.html)。

选择的是官方Production Branch分类；不通过最大版本号推断分支类型。将来更新时重新核对官方分类与补丁、记录版本差异并回归，不能悄悄改变当前规则依据。Linux发行版、内核和CPU架构仍需与官方支持范围匹配。

这是文档和兼容性研究基线，不表示用户集群已安装该驱动，也不表示本机有GPU或做过驱动/H100实测。未执行任何驱动、DCGM或生产采集变更。

## 3. 兼容性与版本门禁

595.112.07发行说明明确要求DCGM 4.3.x或更新版本；现有DCGM准确版本和Exporter版本尚未取得。因此下一步需在不改变现有采集的前提下核对版本，并选定兼容的固定参考版本，不把旧DCGM的字段/行为直接当作R595基线。

若实际是需要Fabric Manager的NVSwitch系统，核对其与驱动的兼容关系；该release列出的Fabric Manager版本为595.112.07，不能因此推断所有H100形态都需要该组件。

该release还列出一个条件性初始化问题：Hopper subrevision=3且VBIOS早于96.00.68.00.xx时驱动不能初始化。实际升级前应核实对应硬件条件；这不表示所有H100都存在问题，也不在本任务中自动执行升级。以上条件均来自[固定发行说明的Known Issues与Software Versions](https://docs.nvidia.com/datacenter/tesla/tesla-release-notes-595-112-07/index.html)。

## 4. 训练场景对规则的影响

| 方向 | 第一版处理 |
| --- | --- |
| 高GPU利用率、高显存占用 | 训练中可能正常；不直接作为硬件故障条件 |
| 低利用率或负载不均衡 | 需训练阶段、作业分配等上下文；没有输入时仅作可选效率策略 |
| ECC、SRAM、行重映射与XID | 核实故障影响和对应输入，优先建设可靠性检测 |
| 温度、降频、功率限制 | 结合设备门槛和限制原因，区分正常功率管理与异常性能损失 |
| 多卡/多机通信 | 多GPU训练时优先核对PCIe、NVLink/NVSwitch、预期链路与对端；按实际拓扑判断，不预设每张卡都有全部链路 |
| 训练任务失败、loss或step-time | 不能仅从GPU指标保证检测；缺少训练框架/作业上下文时保留能力缺口，不擅自增加采集 |

## 5. 核验顺序

先固定H100形态和拓扑，再核对驱动/DCGM/Exporter及采集配置，完成必需字段清单；随后按内存可靠性、XID、温度降频、适用互联和监控健康逐条建卡与测试。当前合成表达式通过状态不升级为H100实测支持。
