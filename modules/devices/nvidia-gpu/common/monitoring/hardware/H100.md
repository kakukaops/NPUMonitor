# 第一版硬件范围：NVIDIA H100

版本：0.2.0；日期：2026-11-06；状态：型号范围已确认，具体现场配置待核实。  
结构化定义：[hardware.yaml](../catalog/hardware.yaml)

## 1. 第一版范围

第一版只围绕NVIDIA H100建立指标、规则和验证文档。H200及其他型号后续单独扩展，不能直接继承H100的兼容结论或参数。物理卡级监控先行；MIG实例级规则仍未准入，不把物理卡级字段重复解释为每个实例的独立计数。

已确认用于训练、不启用虚拟化。Linux设计驱动基线选择R595 Production Branch的595.112.07；DCGM须满足该release的4.3.x及以上兼容要求，具体版本和Exporter待固定。详见[H100训练与驱动基线](H100训练基线.md)。现场PCIe/SXM/NVL、实际软件版本、采集配置和MIG模式仍需核实；不从无虚拟化推导MIG已关闭。

## 3. 每项指标和规则必须回答的问题

1. 它是否适用于H100，以及哪些形态、模式和软件版本？是官方说明、源码线索还是现场实测？
2. 暴露的是物理卡、MIG实例、链路还是整机数据？DRAM、SRAM、纠正/不可纠正、volatile/aggregate是否区分？
3. 对应的DCGM/Exporter字段是什么，是否采集、是否有特殊值、是否存在重复序列？
4. 官方给出的是能力定义、故障标志、错误码、诊断/RMA条件，还是明确的告警判断？不能把不同层次混称为“官方告警规则”。
5. 窗口、持续时间、严重度和恢复策略哪些是项目工程建议，哪些有明确的H100官方依据？

NVIDIA内存错误管理文档将GH100列在部分内存恢复能力的支持矩阵中，但这不能证明每个H100形态、每个Exporter字段均可用；SRAM诊断阈值也不能直接套用到汇总ECC计数。相关资料只作为后续逐项核验入口，不作为当前ECC样例的型号准入证明。[能力矩阵](https://docs.nvidia.com/deploy/a100-gpu-mem-error-mgmt/latest/supported-gpus.html)、[SRAM错误判定](https://docs.nvidia.com/deploy/a100-gpu-mem-error-mgmt/latest/sram-uncorrectable-errors.html)

## 5. 准入与验证边界

型号白名单是“允许研究/适配的目标范围”，不是“已实测支持列表”。启用前需要：准确型号/形态、软件栈版本、设备模式、真实指标样本和标签映射、所需能力及规则验证证据。仅凭modelName字符串或Hopper架构名不能自动认定准入。

当前没有在本机验证真实H100，也没有向现有实验规则加入伪造的H100标签。旧模拟器仍明确标为SIMULATED-GPU。现有合成样本用于验证表达式，不能更名为H100实测结果。
