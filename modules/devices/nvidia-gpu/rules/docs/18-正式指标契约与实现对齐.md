# 正式指标契约与实现对齐

**规范入口：**[第14篇GPU监控指标与告警规则说明表](14-GPU监控指标与告警规则说明表.md)。本轮完成“生产契约与实现统一”，不替代生产发行批准，不关闭完整事件输入、通知失败监控和全规则验收任务。

## 交付内容

| 内容 | 正式入口 | 行为 |
|---|---|---|
| 正式输入定义 | `runtime/src/npumonitor_rules/production-contract.json` | 103项去向、88个数值字段、名称/别名、单位、类型、身份、分类、适用要求和来源 |
| 正式规则目录 | `runtime/production/catalog.json` | 58条规则定义；参数来自正式配置，不读取模拟默认值 |
| 示例配置 | `runtime/config.production.example.json` | 默认未确认；填写源栈后才可能ready |
| 契约编译器 | `production_profile.py`、`selected_catalog.py` | 正式和模拟共享判定代码，传入不同定义；禁止同时选择正式及模拟profile |
| 生成/校验 | `scripts/build_production_contract.py [--check]` | 从第14篇公共派生契约生成，不从模拟目录复制生产契约 |
| 只读源预检 | `python -m npumonitor_rules.cli inspect-source --config … --require-ready` | 不初始化数据库、不发布夜莺规则；不满足输入契约时退出2 |

58条不等于58条全部启用：未选择能力、缺资产或缺输入的规则不运行。新4条质量规则覆盖所有所选数值字段，替代旧input_invalid/input_stale/input_duplicate/field_missing，避免同一质量问题重复告警。通知失败规则继续禁用，不能伪造counter。

## 配置生产输入

1. 复制正式模板到私有配置目录，配置现有Prometheus地址、认证文件、夜莺和通知绑定。
2. 填写`source_contract.stack`：精确GPU型号标签、driver/DCGM/Exporter/NVML版本、PCIe/SXM/NVL形态及`mig_enabled=false`。本版只接受声明为H100物理卡、驱动595.x的范围；这些声明不是对所有该范围版本组合的硬件认证。
3. 核对`source_contract.units`：键是稳定metric_id，值须与第14篇一致。模板列出期望单位，不能直接据此认定现场输出量纲正确。核实后才设置`confirmed=true`。TYPE由Prometheus metadata另行核对；HELP/TYPE不能证明单位。
4. 配置`source_contract.metadata.metric`为设备info指标，默认示例`gpu_info`；`labels`可将正式逻辑标签映射到实际标签名。job/instance/UUID必须原样保留，禁止业务标签替代设备身份。
5. 设备info指标须数值1，每个job/instance/UUID唯一，具有UUID、modelName、driver_version、dcgm_version、exporter_version、nvml_version、mig_mode（值disabled）；版本和型号须与声明一致。如果当前Exporter没有这些信息，需先提供明确的info采集/规范化输入，预检会报告缺口，不伪造版本数据。metadata信息不能自动证明现场硬件能力。
6. 必选数值字段自动选择；条件必选/可选字段按实际能力列入`source_contract.capabilities`。不支持的两项交换机端口字段拒绝选择。每条硬件规则只在所需字段均被选择时启用；可选字段未选择不触发缺字段告警。
7. GPU、交换机和预期端口清单使用`profile.gpus/switches/links`；配置job/instance/UUID或switch_id/link_id。没有预期资产就不承诺缺卡/端口检测。新增数值字段也可列入逐卡required_fields。
8. 使用NVLink能力时显式选择`nvlink_policy=active-only-r595-v1`：0异常，1解除，2未知保持，3不支持。未知不会解除已有硬件事件。

别名仅通过`upstream.metric_aliases`重命名，禁止把两个逻辑指标合并为同一实际名称。单位不一致会拒绝编译；本版不做隐式缩放。现场mW/W、MiB/bytes、mJ/J、ns/seconds或比例/百分比不同时，应先用明确的采集/规范化层转换，再按规范接入，不能只改名。

## 编译与预检

在仓库根目录执行，配置文件应置于私有目录；以下`/private/config.json`替换为实际路径：

```bash
export PYTHONPATH=modules/devices/nvidia-gpu/rules/runtime/src
python -m npumonitor_rules.cli compile --config /private/config.json --output /private/bundle.json
python -m npumonitor_rules.cli inspect-source --config /private/config.json --require-ready
```

正式镜像提供相同命令。预检不更改Prometheus配置，也不在夜莺创建对象。通过后再按[生产运行手册](13-生产规则运行与验收.md)初始化、计划和同步；不要把未确认模板直接覆盖当前模拟配置。

预检输出包括：

- `production_contract.declaration_issues`：源栈、单位、确认或NVLink政策未声明。
- `production_contract.metadata`：逐GPU元数据缺失、重复、陈旧、版本/模式不匹配。
- `production_contract.capabilities`：103项逐项ready/not_selected/missing/unsupported/external/excluded状态。
- `mandatory_input_gaps`：必选数值、元数据或硬件栈输入缺口；存在时不执行硬件判定。
- `mandatory_coverage_gaps`：包括通知、预期资产等更广的覆盖缺口，不能因硬件输入ready而隐藏。
- `rules`：具体规则的缺字段、类型不符、资产未配置以及逐设备缺失/重复/无效情况。

原始样本时间通过timestamp查询获取，不把查询评估时刻误认为采集时间；缺数、未来时间和无效枚举不是健康值。计数单位为seconds时允许小数，不会因0.125秒被误判为整数错误。

`production_contract.ready`只表示所选输入满足执行前提。发布批准始终另行验收；本轮`release_approval=false`。通知缺口不会被伪造成硬件异常，已有硬件事件仍按既有规则保持和恢复。

## 验证与剩余范围

正式契约测试覆盖：正式/模拟互斥、错误单位拒绝、别名冲突、未确认栈阻断、可选能力不误报、逐卡元数据及版本不符、未知NVLink、原始时间戳、秒单位小数计数及新字段资产配置。正式PromQL用例与实际Prometheus只读检查单独记录，不继承“模拟profile已通过”作为唯一证据。

```bash
python modules/devices/nvidia-gpu/rules/scripts/build_master_rule_tests.py --production
# 只读验证生产代码对现有合成Prometheus，不适用于任意现场数据源
python modules/devices/nvidia-gpu/rules/scripts/verify_production_contract.py
```

本次没有重新发布当前夜莺规则，也没有清空模拟源和ML数据。当前本地集成保持显式模拟profile。完整XID事件采集、通知失败counter、所有规则的完整生命周期/故障矩阵、容量长稳及正式版本发行仍按任务清单推进。


本轮验收结果：47项单元/HTTP测试、26项正式PromQL、25项模拟PromQL通过；真实Prometheus只读源预检及独立候选镜像`npumonitor-rules:contract-1.2`预检通过。证据：[正式契约对齐验收](../runtime/evidence/production-contract-alignment.json)。镜像ID记录在证据中；这是本地候选制品，不是已发布的生产版本。
