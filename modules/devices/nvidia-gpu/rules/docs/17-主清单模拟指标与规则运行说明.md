## 模拟覆盖

103项主清单契约均有明确去向：88个数值DCGM字段真实暴露为Prometheus时序；驱动版本、型号、UUID等3项DCGM元数据通过 `sre_sim_gpu_info` 的标签表示；配置/平台功能、外部模拟及能力缺口另外标记。通过 `sre_sim_metric_available{metric_id,mode}` 和 `/coverage` 可核对，不能把capability占位当成原始硬件指标。

2个交换机端口fatal/nonfatal字段的原始语义仍未闭合，保持 `unsupported_semantics`，不输出伪造的健康0。通知失败counter缺口同样保留。作业上下文不在OS SRE范围，不制造任务ID或业务状态。外部电源/进风/风扇/PSU/AER/诊断使用明确的 `sre_sim_*` 示例，不冒充厂商统一字段。

基线为2张合成H100和1个NVSwitch。GPU利用率、SM/DRAM/Tensor活动和功率随时间变化；显存容量与比例满足同一分母约定。能耗累计计数随采样增加；页退休及新版可选字段仅演示显式选择的合成能力，不证明真实H100/R595都能采集。资源忙碌和高显存占用不会自动变成硬件故障。

## 规则配置

保留原核心46项，另增加12项：InfoROM无效、不可修复内存、GPU恢复动作、重映射资源耗尽、热降速余量不足、Fabric Manager错误码、ECC待生效变更、近期功率限制活动，以及新增字段的无效/陈旧/重复/缺失4项质量检测。工程严重度和持续确认仍按独立规则执行，未实现跨规则关联或通知收敛。

温度余量恢复要求大于5℃；近期计数窗口退出表示活动安静。当前模拟NVLink恢复政策仅ACTIVE=1给解除观测，SLEEP=2保持未知/已有事件、不认定硬件故障；新版状态按当前契约处理为版本缺口。这是明确的模拟政策，不宣称通用于真实硬件。

资源容量、GPU/SM/Tensor活动、时钟、能耗和互联吞吐首先供查询/诊断。没有负载预期、显存预留目标或已审定政策时，不编造通用利用率、显存80%/90%等故障阈值。

## 动态数据语义

正常模拟按每张GPU独立相位持续变化，Prometheus每5秒采集。负载周期约4分钟，并叠加较短波动；不代表真实作业画像。

| 类型 | 模拟方式 |
| --- | --- |
| GPU、SM、Tensor、DRAM活动及拷贝利用率 | 随合成负载联动，百分比保持0–100，活动率保持0–1 |
| 已用/空闲显存和使用比例 | 较慢的分配释放波动；已用+空闲=总量−预留，比例从容量计算 |
| 功耗、原始功耗、温度和热余量 | 功耗跟随负载，原始功耗叠加短波动，温度具有相位滞后，余量=降速温度−GPU温度 |
| SM时钟、显存时钟 | SM时钟按负载分档，正常高性能状态显存时钟保持稳定 |
| PCIe/NVLink吞吐、NVSwitch温度 | 吞吐随负载变化，聚合带宽按TX+RX从bytes/s换算MB/s；交换机温度缓慢变化 |
| 累计能耗 | 按采样间隔与功率累积mJ，不随波形下降 |
| ECC、重放、退役页、限制时长等事件累计量 | 正常保持不变；由故障/计数注入递增，不自动制造硬件错误 |
| XID、健康枚举、链路状态、恢复动作 | 正常保持健康；手动场景切换或覆盖改变，保持既有恢复策略 |
| 容量、功率上限、温度阈值、设备元信息 | 保持稳定，避免伪造运行时变化 |

故障场景优先于动态基线，精确字段覆盖优先于场景。正常负载不会自动轮播硬件故障，避免产生无意义告警。

## 逐指标模拟策略与精确注入

正式规范源仍为第14篇。生成的 `runtime/src/npumonitor_rules/master-profile.json` 中，103项 `coverage` 均包含 `simulation` 策略；88个数值字段均显式声明基线、行为、单位及按身份注入方式。`current-simulate coverage` 可查看这些逐项策略。原先隐式回退的零值现已改为明确基线：正常无错误的计数为0，合法枚举、布尔、链路与阈值采用各自契约值。

连续活动指标采用有界、可复现的时间函数；健康状态不会随机翻转。能耗采用相邻采样功率的梯形积分（mJ），计数时间倒退不产生负增量；不表示已模拟真实设备功耗精度。事件计数可选择按秒增长，秒单位累计量保留小数。外部主机功率由各GPU功率加固定主机开销合成，进风温度缓慢变化，风扇随散热需求变化；仍使用sre_sim前缀，不冒充DCGM原始字段。

按稳定metric_id控制指定实体：

```bash
# 指定GPU的InfoROM无效；正常基线不受影响的另一张卡保持健康
bash modules/devices/nvidia-gpu/rules/scripts/sre-rules.sh current-simulate baseline --metric nvidia.inforom_valid --value 0 --identity GPU-CONTRACT-0000
# 指定GPU的NVLink CRC累计计数每秒增加2；不会随HTTP访问次数增加
bash modules/devices/nvidia-gpu/rules/scripts/sre-rules.sh current-simulate baseline --metric nvidia.nvlink_crc --rate 2 --identity GPU-CONTRACT-0000
# 停止注入；既有累计计数不回退，告警仍依各自窗口/恢复策略处理
bash modules/devices/nvidia-gpu/rules/scripts/sre-rules.sh current-simulate baseline
```

`--value`是精确覆盖，故意允许构造无效数据测试数据质量规则；不要将它当作自动一致性修复。`--rate`仅接受已声明counter。健康/布尔/位图通过场景或覆盖改变，XID完整事件请用xid场景，不将最近码覆盖冒充完整事件采集。版本、型号和UUID是标签元数据，预期资产/预期链路由配置提供，采集up和平台状态由真实运行组件产生；未支持的两项交换机字段、通知counter缺口和被排除的作业信息仍明确保留缺口。

## 异常事件轮播（显式测试模式）

正常baseline保持无故障；需要观察事件、状态和计数效果时，启用`current-simulate event_showcase`。这会产生真实本地测试告警，所有输入仍为合成数据；只作用于GPU-CONTRACT-0000，GPU-CONTRACT-0001正常对照。周期600秒，不修改生产规则阈值，也不自动确认XID恢复。

| 相对启动时间/周期阶段 | 合成行为 | 查看指标 |
|---|---|---|
| 首次30秒，此后每300秒 | 产生一次XID79（GPU不可访问类故障示例）；最近码保持79，相同码重复出现也有独立游标/时间 | DCGM_FI_DEV_XID_ERRORS；`current-simulate events` |
| 每周期90—150秒 | NVLink CRC按每5秒1次累计，停止新增时不归零 | DCGM_FI_DEV_NVLINK_CRC_ERROR_TOTAL及increase(...[1m]) |
| 每周期180秒 | 不可纠正ECC累计新增1次；独立注入，不声称与XID79同一故障 | DCGM_FI_DEV_ECC_DBE_VOL_TOTAL |
| 每周期240—300秒 | 功率限制时间增加，时钟限制位设置为软件功率限制示例 | DCGM_FI_DEV_POWER_VIOLATION、GPU_POWER_THROTTLE_SECONDS_TOTAL、CLOCKS_EVENT_REASONS |
| 每周期360—450秒 | GPU温度92℃，余量−2℃，热限制时间累计增加 | GPU_TEMP、GPU_TEMP_MARGIN_CELSIUS、THERMAL_VIOLATION |
| 每周期480—570秒 | 预期NVLink端口状态0；阶段结束回到ACTIVE1 | DCGM_FI_DEV_NVLINK_GET_STATE |

这些是分别验证监控能力的合成故障，不表示多个故障必然同时发生或共享根因；负载基础曲线仍继续。时序累计增量由已运行时间确定，重复抓取不重复增加。XID事件断点保存到模拟卷，重启不会重放已经生成的事件。`sre_sim_xid_recent_event_count`仅统计保留的最近最多1000条事件，不是无限累计counter。

```bash
bash modules/devices/nvidia-gpu/rules/scripts/sre-rules.sh current-simulate event_showcase
# 停止自动注入：累计错误保留，XID告警仍需按事件恢复流程处理
bash modules/devices/nvidia-gpu/rules/scripts/sre-rules.sh current-simulate baseline
```

在夜莺选择原始指标数据源，查看最近15—30分钟。XID用整数状态/事件表或阶梯线展示，不能解释错误码大小为严重度。单看最近码曲线无法显示相同XID的重复事件，应配合事件记录查看。退出轮播后的baseline代表模拟源重新提供正常观测，不构成硬件修复证据。

## 手动注入Web页面

当前本地入口：**http://127.0.0.1:19477/**。无需填写访问令牌。页面提供GPU选择、常用故障场景、停止注入、逐指标数值/累计速率覆盖、查询复制及最近XID事件记录。每次操作替换当前全局注入配置，不支持多个浏览器独立保留不同配置；选择另一张GPU后需再次点击注入。交换机字段在高级区域选择NVSwitch实体。

页面只在当前模拟部署的`FIXTURE_UI=true`时启用，生产规则镜像不包含模拟页面。现有带令牌的控制API继续保留；页面使用同源JSON接口，不把管理令牌传到浏览器。端口仍仅绑定127.0.0.1；从其他电脑访问需先通过SSH本地端口转发，不直接公开模拟管理端口。

“停止注入”恢复正常输入，不清除累计计数、历史事件，也不会自动执行XID/SXID恢复确认。页面每5秒刷新当前源配置；是否已触发告警、通知是否成功以夜莺为准。
