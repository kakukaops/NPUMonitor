# v2实施与验证

日期：2026-11-12。

## 实施内容

- 新增单指标12步因果时序预测及稳健残差/水平检测。
- 新增可选PCA多指标联合检测、自定义不可变指标schema及贡献输出。
- 新增按GPU/指标批量配置API和Web入口，幂等展开，不自动训练/发布。
- 历史训练、影子、发布回滚及回放复用既有模型管理链路；旧模型和结果保留。
- 事件处理留在夜莺；不新增本地跨模型事件聚合。

## 验证记录

最终验证结果见本轮机器可读证据`evidence/gpu-v2/`。旧`evidence/gpu/`只证明v1当时版本，不作为v2自动通过凭据。

## 后续准入计划

1. 真实GPU历史与负载阶段数据准入、字段与时间核验。
2. 正常/异常回放及人工标注，确定每类指标的窗口和误报预算。
3. 基于增量价值决定是否启用联合模型，不固定GPU检测目标数量。
4. 窗口查询批处理/缓存、容量与故障压测，完善单实例之外的运行方案。
5. 在告警处理侧验证同GPU跨检测器关联、通知合并与恢复语义。

## 本轮实际结果

- 最终镜像15项核心测试通过，包括因果前缀一致性、缺口不跨窗、联合关系异常、制品保存恢复及原有生命周期测试。
- 批量展开2项单指标配置与1项自定义联合配置，重复请求不重复创建；viewer写入拒绝、非法指标拒绝。
- 三项模型均从既有Prometheus最近30分钟取得901个模拟GPU源样本完成训练、测试自检与发布。这里的901只是当次计数，不是生产建议训练长度。
- 首次较短窗口模型保留测试异常率约11.48%，被程序标记review_required并拒绝发布；没有放宽门槛，改用更长历史后通过。该现象也提示需要现场正常负载覆盖和误报评估。
- 三项在线输出与历史回放字段契约通过。新温度时序配置触发夜莺事件383，并在正常源数据后恢复；实际Webhook触发/恢复记录见final.json。
- 实际更换镜像并重建容器后，3个在线模型指针、自定义指标组和查询窗口恢复通过；最终三项v2检测均无活动异常，/ready为200。
- 使用当前实际API载荷完成六页DOM渲染、批量配置表单和单/多指标算法过滤测试；这是纯Node契约测试，浏览器视觉/点击验收not_run。
- 目录检查通过，45份原规则冻结载荷未变。
