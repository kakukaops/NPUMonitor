# v5训练解耦实施与验收

日期2026-11-12，版本0.5.0。目标：先独立当前训练部分，未来可替换公司训练/部署平台；不在缺少API文档时臆造真实对接。

## 已实现

- model_platform独立进程、API、数据卷、任务/制品/部署Registry与备份恢复。
- model_runtime共享算法库，backend保留旧导入路径兼容层。
- ModelBackend端口、Http参考适配器和监控侧数据导出/作业协调器；Engine无fit/save调用。
- 平台幂等、任务查询/取消，监控重启同步pending_sync；响应身份、数据摘要、输入schema和源时间检查。
- 部署成功才切换在线指针，旧本地模型继续推理回滚；平台失效不伪造正常。
- 新模型校准/集成/回放走平台；旧制品修改需要重训到目标后端。
- 监控与平台独立备份范围，不把远程权重混称监控备份。

## 当前验证

最终证据位于evidence/gpu-v5。公司接口只做可替换契约桩，不宣称真实公司训练或部署已调用。真实GPU数据效果和生产HA不在本轮测试范围。

## 使用

```bash
# 启动监控及独立参考模型服务
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh simulation-up
# 只启动模型服务，不要求监控API在线
GPU_ML_SIMULATION=true bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh platform-up
# 平台独立日志/备份
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh platform-logs
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh platform-backup
# 回归与实际链路
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh test
docker compose -f deploy/nvidia-gpu/ml/compose.yaml exec -T gpu-ml python < modules/devices/nvidia-gpu/ml/scripts/verify_v5.py
python modules/devices/nvidia-gpu/ml/scripts/verify_v5_operations.py
```

最后一项会实际停止/重启两个服务并恢复，仅用于当前模拟实验；不要在生产未经计划执行。配置GPU_ML_MODEL_PLATFORM_URL只适用于内部协议兼容的服务/桥接，不是任意公司原生模型URL。

## 最终验证结果

- 39项监控/契约/既有模型测试＋6项独立平台测试通过，共45项。含公司端口桩替换、重启后外部任务同步且不重复提交、取消、幂等、源时间/身份校验、旧制品及现有四场景回归。
- 实际从Prometheus导出1801点，独立平台训练完成；监控未创建该新版本joblib，只保存平台引用和源快照。该计数是实验输入，不代表生产训练建议。
- 部署回执成功后切换指针，HTTP在线推理通过；后处理、冻结集成和回放通过平台API完成。旧本地在线版本回滚后可再次发布API版本。
- 实际停止模型平台：已有异常和源水位保持，未伪造正常证据。重启平台后原platform_id/部署身份保持，恢复调用并按新鲜正常证据解除。
- 实际停止监控服务：独立模型平台仍能训练已导出数据、部署和评分，之后监控恢复。不是只换目录或mock推理。
- 两侧备份/空目录恢复分别通过。监控备份含4个远程引用并明确不含远程权重；参考平台备份恢复5份模型，2个已部署版本评分成功、平台身份保持。
- 参考平台镜像不包含gpu_ml.engine/source/nightingale模块，监控镜像不包含训练服务包；算法共享库和历史兼容层保留。
- 使用实际API载荷完成7页DOM契约检查，浏览器视觉/点击not_run。
- 模块目录检查通过，45份原冻结载荷保持一致。
