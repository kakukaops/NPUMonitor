# GPU机器学习监控模块需求文档

版本：0.3；更新：2026-11-17。状态：两类核心能力的需求基线，文档更新不代表新增功能完成。

关联：[技术方案](02-技术方案.md)、[项目计划](03-项目计划.md)、[指标映射](04-GPU指标与检测场景映射.md)。本文替代原需求主线；历史验收只证明对应版本与环境。

## 1. 目标与范围

构建两种核心能力：**单指标动态基线与异常检测**、**多指标联合异常检测**。两者共用数据接入、训练、回放、模型管理、在线判定和夜莺事件链路。当前以DCGM已有连续指标为输入，单张物理GPU为分析实体，不要求作业、吞吐、阶段或环境温度。

GPU温度、功耗、时钟等是能力的应用对象；四类DCGM条件关系和残差漂移是多指标能力的应用模板，不替代两类通用能力。硬规则继续独立运行，ML不作为ECC、XID等规则的前置确认。

## 2. 能力一：单指标动态基线与异常检测

配置单位为数据源/集群＋GPU UUID＋单个指标。用户选择GPU、指标和可信历史范围，训练并发布后，查看实际曲线、随历史走势变化的当前点正常参考、参考范围、异常点和事件。

“动态”指参考值随此前观测变化，不仅是实际曲线实时刷新或固定阈值展示；不等于模型参数自动更新，也不要求向未来预测一段曲线。本期以用过去样本预测当前点为基础。日/周周期、长程趋势、随工况变化的区间宽度及在线自适应列为后续评估项，不宣称已实现。

| 编号 | 需求与验收口径 |
|---|---|
| U-01 | 未配置或未训练时可查看实际曲线，明确无模型结论，不补造参考值 |
| U-02 | 当前点预测仅使用此前源样本；增加未来数据不能改变已有点的预测和判定 |
| U-03 | 展示原单位实际值、动态参考与有效参考带；说明参考带的算法、适用性和非概率语义 |
| U-04 | 分别识别突发偏离和相对自身历史的持续水平变化；评估缓慢漂移的检出及被参考追随的风险，不承诺全部检出 |
| U-05 | 同时展示异常分数、阈值和触发分量；参考带内因水平项触发时可解释，不把参考带冒充完整判定边界 |
| U-06 | 正常高负载、空闲、正常水平切换作为反例评估；无上下文时只称统计变化，不称硬件故障 |
| U-07 | 缺失、陈旧、无效值和不连续窗口显示未知/未评分；新鲜正常证据才允许恢复 |

仅评分的level_mad可作为比较候选，不能单独算作“动态基线能力”完成。

### 2.1 指标适用性与首期范围

动态基线不对全部GPU数值指标开放。依据[指标适用性清单](15-GPU指标动态基线适用性与准入.md)逐项选择：A首批验证GPU/HBM温度、实际功耗、GPU利用率和显存控制器活动率；B有条件评估SM/显存时钟、显存占用及后续连续遥测。状态/开关、错误码、枚举、位图、配置门槛和静态容量不直接建动态基线；累计量须先定义转换，稀疏错误计数优先规则。

新增U-08：字段选择受语义与实现能力双重约束，页面解释不可选原因；预检报告连续覆盖、常量/离散档位、零值占比、配置切换及历史可预测性。训练点数足够不等于适用，合法空闲零不等于缺失。已存在的8字段入口需按5项首批、3项条件候选分级，尚待实现，不在文档更新时改变运行行为。

新增U-09：动态基线效果按字段与设备分别验证，与简单参考比较；无法稳定预测或没有告警增益时保留原始曲线/规则或影子，不强行发布。派生特征有单独metric_id追溯、公式、单位、窗口和reset契约，当前不支持的转换不能提交训练。

## 3. 能力二：多指标联合异常检测

配置单位为数据源/集群＋GPU UUID＋不可变指标组，至少两个指标。字段同样遵循适用性清单；开关/事件不直接加入当前PCA或森林，配置背景仅通过显式模板参与可比性判断。分析同卡多个指标的组合及关系，不是多个单指标告警的逻辑合并。例如各指标均未越硬阈值，但相同负载下温度偏高，或功耗与时钟组合偏离历史关系。

| 编号 | 需求与验收口径 |
|---|---|
| M-01 | 用户可选择指标组；校验单位、同实体源时间、必要输入和有效重叠数据，输入不足时不可评估 |
| M-02 | 通用联合检测学习组合分布/关系；单项未越硬阈值的关系破坏用例须单独验证 |
| M-03 | 输出联合分数、阈值、异常点和事件；算法支持时输出重构参考、残差或贡献，不支持时明确为空 |
| M-04 | PCA重构参考与单指标当前点预测明确区分；贡献只表示评分证据，不解释为因果根因 |
| M-05 | 条件模板明确目标指标与条件指标，输出条件基线、可比范围和残差；范围外不能产生有效正常结论 |
| M-06 | 长期残差漂移作为扩展模板，有独立参考历史和时间窗口；短实验不能冒充长期硬件退化证据 |
| M-07 | 正常联动升降、空闲、正常负载切换及缺一必要指标作为反例；模型局限与误报需记录 |

当前通用联合检测为同一时刻的多指标组合分析，通用多指标时序依赖学习、跨GPU比较和自动可比组不在本期承诺中。特定条件/漂移模板使用历史窗口，不等同通用多变量时序模型。

## 4. 公共功能与数据要求

| 编号 | 需求 |
|---|---|
| C-01 | 只读接入现有Prometheus；以集群/源范围＋GPU UUID识别实体，设备更换不继承旧状态 |
| C-02 | 使用正式指标规范，核对名称、单位、值域、sentinel和采样；缺失、陈旧、重复、NaN/Inf先拦截，不补零或插值制造证据 |
| C-03 | 选择算法和已训练模型分开；训练前预检历史覆盖，异步训练可取消，失败保留旧在线模型 |
| C-04 | 按时间进行训练/校准/比较/最终测试，保留快照和版本；无标签不把异常比例当误报率 |
| C-05 | 支持回放、候选比较、影子、人工发布与回滚；不同实体、输入或采样不兼容时拒绝复用 |
| C-06 | 正常/异常/未知分离，重复样本不推进确认，未知保持已有异常；暂停和退役使用管理原因 |
| C-07 | 页面按两类能力组织，按模型能力展示图例、区间和解释；模型切换不重算既有在线历史 |
| C-08 | 夜莺承接事件与通知，规则/ML/质量/平台状态分别展示；保持旧规则及通知授权边界 |
| C-09 | 角色权限、审计、查询预算、单写者、备份恢复和健康监测沿用现有机制；远程权重由平台单独备份 |
| C-10 | 训练、制品、部署与评分由独立模型服务执行；监控侧负责数据质量、编排和持久证据 |

来源类型区分simulated、replayed和真实源状态，真实未核验不能视为已准入。MEM_COPY_UTIL是显存控制器活动，不是容量占比或吞吐。Counter、枚举、码值和位掩码不能未经专门转换直接套连续量模型。当前无上层上下文，不推断训练失败、产出能效、硬件老化或剩余寿命。

## 5. 完成与准入

两类能力分别验收，不能以平台拆分完成、四类场景完成或链路可运行替代能力验收。先核对算法契约、模拟反例、UI解释和异常/未知/恢复链路，再使用真实GPU历史进行回放及旁路验证。

真实准入需约定每GPU日/每配置的事件误报预算、检出延迟、有效评分覆盖和人工处理成本；有标注时报告对应范围召回与正常误报，未标注范围明确未知。异常点、持续确认事件和通知的延迟分开计算。

当前已有两类检测器、曲线与生命周期基础及历史模拟链路证据；单指标解释展示、双能力专项验收、真实长期效果和容量仍需按[项目计划](03-项目计划.md)补齐。浏览器实际交互/视觉尚未验收，不以DOM或语法检查替代。
