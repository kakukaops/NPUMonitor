# GPU机器学习异常检测技术方案 v3

更新：2026-11-12。替代[v2方案](02-技术方案-v2历史.md)。本轮借鉴Merlion的组件组织方式，独立实现，不引入Merlion运行依赖、源码或其NumPy约束。研究依据见[Merlion评估](<../reports/Merlion 监控异常检测适配评估.md>)。本方案只覆盖机器学习检测及结果输出，夜莺负责事件生命周期与通知；跨检测器事件合并仍需在告警处理侧实现和验证。

## 1. 目标与配置单位

GPU＋单指标时序或GPU＋不可变指标组为检测配置。Web批量展开配置，不要求预先枚举固定GPU故障目标数量。单指标按卡×指标展开；联合按卡×指标组展开。当前训练制品逐配置独立，算法接口共享；跨卡共享模型、自动分组不在本轮。所有新配置均需真实源历史训练和人工发布；显式模拟环境也只从Prometheus历史训练，不回退伪造历史。

## 2. 组件流水线

```text
Prometheus只读适配 / 源时间与数据质量
  → StrictPreprocessor（identity或训练集robust_scale；不插值）
  → Detector.fit / score_raw（原始评分分量）
  → QuantileCalibrator（独立校准段定标）
  → ThresholdPolicy（阈值、倍率、异常判断）
  → 持久化证据与持续确认 → 夜莺结果网关
```

检测器只负责训练和原始评分，不管理阈值、会话、源查询或事件。协议见[扩展接口](07-模型扩展接口.md)。每段都有版本身份，模型制品包含检测器、预处理参数、校准器和判定配置。原始分数不能跨算法直接比较；校准分数也不是故障概率。默认取非负评分分量的99%分位数作分量尺度，再取校准最大分数的99.5%分位数为阈值，均可显式生成新校准版本。

预处理只在训练段fit，校准只在校准段fit。robust_scale保存中位数和MAD尺度；参考值/参考带反变换回原指标单位。缺失、非有限值、重复或非递增源时间拒绝，不对缺口插值。单指标滞后窗口对采样间隔偏差容许25%，不跨缺口；2秒轮询不是强制所有模型采样周期2秒。

## 3. 当前检测器与能力声明

| 算法 | 类型和原始评分 | 参考能力 |
|---|---|---|
| temporal_mad | 过去N样本Ridge预测当前点；预测残差与历史水平偏离两个分量 | 当前点预测＋稳健残差带，不是概率置信区间 |
| level_mad | 单指标相对训练中位数的MAD尺度偏离，无时间窗口 | 仅评分，无灰线/区间 |
| joint_pca | 标准化PCA重构残差及潜空间距离 | 联合重构参考，不是预测，无预测区间 |
| joint_iforest | 多指标Isolation Forest负score_samples | 仅评分，无灰线、区间或贡献根因 |
| ensemble_max | 冻结成员的校准分数/各自阈值取最大值 | 仅评分，无人为平均预测线 |

temporal_mad默认12点，训练接口支持4至60点，Web提供常用窗口。历史水平项可能把正常负载切换认作异常，需要工作负载分组和现场验证。level_mad只提供无预测的轻量候选，不冒充时序预测。PCA是联合点异常，不声称学习任意非线性或长程依赖。所有当前适配器声明online_update=false、stateful=false；不添加未验证的在线学习开关。

能力声明包含历史样本数、采样周期、参考类型、是否有参考带/贡献指标、是否支持在线更新和制品schema。页面根据声明显示/隐藏参考线图例与区间；无能力的字段为空，不伪造。不同制品/判定版本的曲线连接断开，避免跨版本造成连续预测假象。

## 4. 时间顺序训练与评价

新流水线按源时间严格切分：训练60%、校准20%、候选比较10%、最终测试10%。各分段独立构建历史窗口，不跨分割借用上下文；不随机打乱、不用最终测试挑选候选。最少240源样本只是程序门槛，长窗口或较慢周期可能要求更长历史，生产历史范围需覆盖正常负载变化与季节性。

训练报告记录时间边界、有效评分覆盖、未评分数量、缺口、异常点比例、检测条件持续段数量和实际评分耗时。有明确fault/normal_change标注时才计算对应范围的点召回、正常标注告警比例、标注精确率和故障区间首次检出延迟；collection_problem/unconfirmed不当作正常，未标注点不当作正常。持续段是检测条件而非夜莺事件。延迟为原始模型首次异常样本延迟，不含持续确认/通知延迟。

程序继续保留最终测试异常点比例10%的发布自检门槛，它不是准确率、现场误报预算或生产准入标准。无标签不能宣称最佳模型或最低误报；回放不会改变模型或在线状态。

## 5. 独立版本、候选与集成

训练生成新制品但不自动发布。校准/阈值变更以父版本创建新制品：阈值调整保持检测器、预处理和校准器不变；重新校准只使用原快照校准段，不重训检测器或预处理。两者重新计算比较段/最终测试报告，保留父版本、快照摘要和各组件身份，仍需手动发布。旧sensitivity接口保留兼容，在线结果额外记录任务配置revision和有效倍率。

候选比较读取一次Prometheus历史，所有候选使用同一源快照和60/20/10/10切分，单独生成模型报告；自动赢家固定为空，人工根据比较段与标注审查，最终测试只作保留验证，不能反复根据测试结果调参后继续称独立测试。比较不会切换在线指针。

手动集成仅接受2至3个相同实体、输入、源、快照和切分且通过自检的v3成员，不允许嵌套。成员冻结进入制品，使用各自阈值归一后的最大分数，不自动选择成员，也不承诺集成优于单模型。集成只支持独立阈值调整；改变成员校准需创建成员版本后重建集成。

## 6. 持久化与API

沿用SQLite WAL、模型/快照SHA256、可信本地制品、单写租约、备份恢复与7天在线结果保留。schema1旧模型可继续运行、回放和回滚；原始分数不可追溯时明确为空并标明legacy，不由旧校准分数伪造原始分数。schema3新制品独立保存，旧结果不覆盖。

| API | 用途 |
|---|---|
| POST /policies | 批量创建GPU/指标配置，幂等 |
| POST /training-jobs | algorithm、pipeline预处理/窗口/校准配置、起止时间与step；可选labels |
| POST /models/{id}/postprocess | 由父版本生成校准/阈值版本，不自动发布 |
| POST /comparisons；GET /comparisons/{id} | 同源候选作业与报告 |
| POST /ensembles | 手动冻结成员集成版本，不自动发布 |
| POST /replays；GET /replays/{id} | 时间回放，可选明确时间段标注；报告不改在线结果 |
| GET /state；GET /series/{task} | 模型能力、组件版本、分数和线上证据 |

所有路径以/api/gpu-ml/v1为前缀，管理操作沿用角色鉴权和审计。Demo角色自选登录保持用户此前要求；生产关闭GPU_ML_DEMO_LOGIN。影子计算错误与主模型隔离；重复源样本不推进确认，输入失效不假恢复。结果网关不是通用PromQL，夜莺按既有接入契约读取。

## 7. 实施与生产门禁

本轮已实现上述独立接口、流水线、能力驱动图表、时间评估、候选比较、手动冻结集成和版本管理。运行与证据见[本轮验收](09-v3流水线实施与验收.md)。旧v1/v2证据仅证明当时版本。

仍需现场完成真实H100和作业阶段数据准入、故障/正常样本标注、窗口及阈值预算、误报和检出评价、查询容量/缓存/分片与HA、漂移检测重训策略和在线更新检查点设计。当前单实例实现和模拟验收不是生产效果或可用性认证，不依赖Merlion上游继续维护。
