# GPU ML 运行与接入指南

版本：0.1.0。当前提供独立可运行预览版，复用既有夜莺9.3.0与Prometheus。真实H100、生产规模和浏览器视觉准入单列，见[实现验收](06-实现与验收报告.md)。

## 1. 已实现内容

- GPU实体发现、同源指标查询、字段质量与覆盖；模拟/真实未核验来源分开。
- GPU/HBM条件温度、功耗与SM时钟关系、明确运行上下文中的活动变化三类模板。
- Ridge + Isolation Forest组合及条件基线 + MAD适配器；真实查询历史训练、快照、校准、保留测试。
- 模型选择复用、异步训练/取消、影子运行、发布回滚、独立历史回放与反馈。
- SQLite WAL持久状态、源时间去重、3次新鲜异常确认与3次新鲜正常恢复，未知保持既有异常。
- 专用结果网关、夜莺受管业务/质量/平台规则、原生事件与恢复记录、本地测试通知。
- 独立Web、viewer/operator/admin令牌、HttpOnly会话、版本冲突检测与审计。
- 模型/快照/数据库一致性备份与空目录离线恢复；单写者租约、源绑定及丢卷保护。

独立页面地址：**http://localhost:19460**。旧通用原型仍在19450，旧GPU规则综合演示仍在19430，三者不是同一个模块页面。

## 2. 首次启动与登录

先确保既有 `deploy/nvidia-gpu/lab/compose.yaml` 的夜莺、Prometheus和本地测试通知接收器正常运行。新模块通过外部Docker网络 `gpu-alert-lab_default` 连接，不重建这套共享底座。

从仓库根目录执行：

```bash
# 显式GPU模拟预览；仅为隔离实验Prometheus增加GPU模拟job并热加载
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh simulation-up

# 只在本机终端显示访问令牌，复制所需角色令牌到登录页
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh credentials

bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh sync
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh status
```

令牌和认证文件存于私有 `.local/`，不提交、不通过聊天或页面API返回。容器以非root用户运行，所需文件只读挂载；宿主机 `.local/` 目录应保持私有。管理员可管理集成、推理和备份，操作员可管理任务/模型，viewer只读。

初次镜像构建会复用本模块demo的固定数值计算基础镜像；不存在时脚本先构建它。正式发布应在目标环境锁定并保留镜像及依赖，不能假定其他机器已有本地镜像。

## 3. 页面操作

### GPU总览与在线检测

总览列出源中可发现的物理GPU，身份为cluster + UUID；MIG实例暂不准入。点击设备查看指标与检测。未建立任务的GPU可以只看原始曲线，不伪造模型评分。

在线曲线保存当时实际输入和模型版本，不因切换模型重算历史。参考带为训练残差±3尺度的解释辅助，不保证生产覆盖率，也不是森林阈值。分数不是故障概率。

模拟控制仅在显式模拟profile、`GPU-ML-SIM-*`设备出现。异常注入持续90秒后恢复；缺失/陈旧/重复等质量场景需手工恢复。模式持久化，服务重启不会把缺数偷偷改回正常。

### 任务与模型

1. 创建任务，选择GPU、模板和算法；预检当前必需输入。
2. 选择已有兼容模型，或从Prometheus历史发起训练。
3. 查看校准/保留测试报告，在影子模式或回放中对照。
4. 发布后在线生效；发布不清空已有异常。需要时回滚到上一版本。
5. 暂停或退役任务按管理原因关闭；保留模型、历史和审计，不称硬件修复。

模型复用限定同一实体、模板和来源类型。新设备不能未经验证直接使用另一张卡的模型。退役任务不会因重启重新启用。

历史训练至少180个有效唯一源样本，预设最小窗口6分钟；窗口有效覆盖至少80%，起止历史必须存在。对模拟profile，已记录故障窗口用于排除训练样本，不作为推理特征。真实场景需主动选择可信训练窗口，不能把旧规则事件自动当完整真值。

训练数据按60%/20%/20%时间顺序切分；默认保留测试点异常率超过10%的版本需要复核，不能直接发布。该门槛是预览自检，不是生产告警准确率标准。

前台“最近1天”训练按30秒步长查询，长窗口仍受点数限制；现有Prometheus保留3天，不支持凭空训练14天。取消排队作业立即生效，运行中在受控检查点取消；完成作业不能再取消。

影子结果单独保存，不参与告警状态；回放也不创建在线事件或覆盖在线历史。

## 4. 夜莺对接与通知边界

本模块使用“GPU机器学习监控”业务组和“GPU-ML持久结果”数据源，受管标记为 `gpu-monitoring-ml`。结果网关地址为内部 `http://gpu-ml:9460`，只支持以下固定契约：

```text
1+1
gpu_ml_active{detector_id="<稳定任务ID>"} == 1
gpu_ml_platform_unhealthy
gpu_ml_input_unhealthy
```

不支持任意PromQL或通用查询代理；未支持表达式返回422。推理心跳失效返回503而不是成功空向量；已确认异常在源缺数时仍保留。质量和平台异常另立规则，不把它们当GPU硬件恢复。

任务创建、启停和改名由后台定期对账；重命名保持同一规则ID。发现非受管同名对象、表达式或数据源被手工改动时停止覆盖并显示同步异常。不会覆盖旧GPU规则。

当前自动对接严格验证既有本地测试通知规则最终指向 `http://notification-receiver:9080/webhook`；其他出口拒绝自动绑定。正式环境的组织、通知和权限适配需要单独配置及验收，当前不自动向外部人员发消息。

事件页显示夜莺实际返回的本模块活动/恢复记录，以及与已发现GPU相关的既有规则活动事件。读取范围目前是24小时、有界条数；不是全量历史事件平台。本地episode_id不等于夜莺事件ID，关联依赖规则、hash和原触发时间。

## 5. 真实数据接入

```bash
GPU_ML_PROMETHEUS_URL=https://your-prometheus.example \
GPU_ML_NIGHTINGALE_URL=https://your-nightingale.example \
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh up
```

`up`不添加采集任务、不向原始Prometheus写入、不启用模拟冷启动。不要在一个已绑定实验状态卷上直接换成另一生产数据源：模块会拒绝源/字段契约变更；使用独立部署工作区/卷或先设计显式迁移。

字段绑定在 `config/bindings.json`，需要根据实际DCGM/Exporter输出核对。当前数值范围是预览保护配置，不是NVIDIA统一硬件故障门槛；真实源显示real_unverified，不能仅因字段存在就判H100准入。

Prometheus可使用系统默认TLS验证；Bearer或Basic认证由 `.local/gpu-ml-prometheus-auth.json`只读挂载，默认 `{}`。文件可按以下结构配置，真实凭据只保留在本机：

```json
{"type":"bearer","token":"<secret>"}
```

或：

```json
{"type":"basic","username":"<user>","password":"<secret>"}
```

凭据不放URL，认证文件变更不触发模型源绑定迁移。当前客户端绑定一个数据源，不提供多租户数据源管理台；生产鉴权、业务组边界和查询预算需结合现场明确。

## 6. 数据与备份恢复

持久卷：`gpu-monitoring-ml_gpu-ml-data`。包含数据库、模型、训练快照、备份和运行验收。原始遥测仍在现有Prometheus；在线派生结果默认保留7天，单次展示最多12000点，长窗口需注意截断标志。

```bash
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh backup
```

也可在管理员页面生成并下载包含SQLite快照、模型和训练快照的tar.gz。备份记录SHA256。应定期将备份移至独立存储并清理历史；当前不会自动外传备份。

离线恢复入口：

```bash
python -m gpu_ml.cli restore /backup/archive.tar.gz /empty/restore-directory
```

在服务容器工具环境使用，目标必须为空；拒绝路径穿越、符号链接、错误schema、损坏数据库/模型/快照。先验证空目录恢复，再按运维流程停止服务并替换数据，不对运行卷执行覆盖。当前schema为1，跨schema升级需显式迁移，不宣称任意旧镜像可读取未来数据库。

初始化保护文件为 `.local/gpu-ml-initialized`：初装允许pending，启动成功后为initialized。已有安装丢失数据库时拒绝自动重建健康状态，需从备份恢复；不要通过删除保护文件绕过。

## 7. 验证与排障

```bash
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh test
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh verify
python modules/devices/nvidia-gpu/ml/scripts/verify_restart.py
bash modules/devices/nvidia-gpu/ml/scripts/gpu-ml.sh logs
```

`verify`和重启验收会实际切换模拟场景并产生本地测试通知，必须串行；不对真实GPU执行故障注入。管理与平台补充验收脚本分别为 `scripts/verify_management.py` 和 `scripts/verify_platform.py`，在服务容器内通过stdin执行，见验收报告。

查看 `/health`确认进程，`/ready`确认推理/源链路；两者含义不同。无输入、未训练、缺少job上下文、源认证失败和未知GPU不能显示为正常。平台页面显示查询计数、失败、心跳、同步异常和审计。

当前单进程单活动写者，通过文件锁拒绝同卷多写；训练线程与在线线程分离。不是HA架构，生产GPU数量、查询预算和磁盘容量须按真实规模压测。
