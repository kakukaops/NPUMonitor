# 远程模型接入与已有部署登记（0.7.0）

更新：2026-11-17。已实现多个HTTP模型服务的登记与按模型引用路由。客户原生API、真实跨机器链路和真实GPU效果尚未验收；同机参考服务的API验证不能写成客户远程平台已接入。

## 用户路径

1. 管理员进入“基线与训练 → 模型服务连接 → 接入远程模型服务”，填写名称、基础URL、Bearer凭据、超时。先调用平台info验证身份，成功才保存连接。地址与平台身份不可在原连接上静默变更；新平台应新增连接。
2. 在动态基线页选择GPU与指标，点击“登记远程已有模型”；也可从“选择模型”弹窗进入。选择已登记服务，读取兼容模型目录，或手工填写模型引用与可选已有部署引用。
3. 系统核对设备、来源、完整输入schema、指标metric_id/单位、窗口/采样和输出能力，发送当前任务必要指标的最近有效窗口试评分。此步骤不要求本系统训练、不下载模型文件、不写在线异常、不切换在线指针。
4. 通过后登记版本，回到“选择模型”查看执行位置和验证结果，手动启用。已有就绪deployment_ref会复用并重新核对身份；没有部署引用时，发布通过所属平台deploy接口部署，成功后才切换。
5. 超时、接口错误或身份/源时间不匹配保持未知与已有异常；失败不静默切回本地模型，也不输出正常值。

“历史训练”仍使用默认训练后端（GPU_ML_MODEL_PLATFORM_URL及其适配器）。新增连接用于已有模型的多服务调用，不提供多训练平台任意调度。原模型、图形、校准入口保留；外部登记模型没有本地训练快照，重新校准/集成应在所属平台完成，再登记新版本。

## 必需模型协议与桥接

当前实现为HttpModelBackend标准协议。自定义ModelBackend可继续接公司SDK；用于已有模型登记时还需实现目录/描述及已有部署查询端口，未支持时明确unsupported。仅输入任意公司预测URL无法完成接入：桥接需负责认证、字段/单位、输入窗口、预处理、评分/阈值、模型/部署版本和错误映射，不能把预测值直接当异常分数。

| 模型平台接口 | 作用 |
|---|---|
| GET /v1/info | contract_version=1、稳定platform_id；声明平台操作 |
| GET /v1/models | 返回platform_id与models数组；每项为模型描述。目录可选，缺少时手动输入引用，但描述仍必需 |
| GET /v1/models/{model_ref} | 返回不可变模型版本的描述 |
| GET /v1/deployments/{deployment_ref} | 返回platform_id/model_ref/deployment_ref/status；已有部署必须ready |
| POST /v1/deployments | 尚未部署版本的部署；可复用原接口 |
| POST /v1/models/{ref}/predict | 未部署模型试评分/回放 |
| POST /v1/deployments/{ref}/predict | 已部署模型试评分/在线推理 |

模型描述至少包含contract_version、platform_id、model_ref、entity、source_type、feature_schema、input_contract、capabilities、status；algorithm、created_at、training_window、report、pipeline、deployment_ref补充展示和部署信息。参考平台支持从不可变原请求恢复旧版本实体元数据；旧模型没有单位契约时不会自动推断为已验证兼容，应在平台补齐可信契约或重训。

input_contract按必需字段逐项声明，例如：

```json
{"gpu_temp":{"metric_id":"nvidia.gpu_temp","unit":"°C"}}
```

entity必须匹配当前任务实体，source_type区分simulated和real_unverified；feature_schema必须与任务一致。该实现沿用现有ML实体身份，正式job/instance/UUID迁移缺口未因此关闭。输入单位必须和当前绑定完全一致，不能靠重命名实现单位转换。capabilities包含history_samples、cadence_seconds、reference_kind；支持none/causal_forecast/joint_reconstruction/conditional_baseline。当前只支持冻结、无状态评分，不登记有状态在线更新模型。

预测请求/响应沿用[内部接口契约](13-模型平台接口契约.md)。响应中平台/模型/部署身份、源时间、原始观测、分数/阈值、异常判定及参考输出均受校验。声明能输出参考曲线却缺目标expected的模型拒绝登记。试评分通过仅证明连接和输入输出兼容，不代表故障准确率、误报预算或生产准入。

## 监控API

全部路径前缀/api/gpu-ml/v1。

| API | 权限与作用 |
|---|---|
| GET /model-services | viewer及以上；返回脱敏连接信息与默认服务 |
| POST /model-services | admin；name/url/token/timeout_seconds，检查连接后保存 |
| PUT /model-services/{id}/credentials | admin；验证新token与原platform_id，成功才替换凭据 |
| POST /model-services/{id}/check | operator及以上；连接与平台身份检查 |
| GET /model-services/{id}/models?task={task_id} | operator及以上；读取并筛选兼容模型目录 |
| POST /remote-models/register | operator及以上；service_id/task/model_ref/可选deployment_ref，试评分后登记，不发布 |
| POST /tasks/{id}/publish | 沿用发布入口，按所选模型的backend_id调用对应服务 |

每个服务使用独立不可变backend_id；不同平台上相同model_ref不能串用。登记标识绑定任务/服务/平台/模型/部署，重复登记幂等。服务响应携带的URL不作为下载或重定向目的地。

## 凭据与恢复

新增服务凭据写入监控私有卷model-service-secrets（目录0700、文件0600）；API、模型记录、审计和普通监控备份不包含token。默认服务凭据仍由原有只读secret挂载。新增服务地址/元数据包含在数据库备份中，凭据需单独安全保管；恢复后可用“更新凭据”入口重新配置。失败不替换原凭据；平台身份变化时拒绝沿用旧引用。

外部登记模型没有snapshot/artifact，备份恢复按远程引用验证，不伪造本地制品。远程权重和训练快照由所属平台单独备份；监控侧仅恢复引用不能恢复远程权重。缺凭据/平台不可用时未知，不回退本地权重。

## 验证记录

- 49项监控单元测试、9项模型平台测试通过；覆盖输入语义/单位、目录兼容筛选、登记幂等、已有部署复用、凭据权限/原子更新、错误保持与无本地快照的备份恢复。
- 前端契约覆盖固定“选择模型”入口、远程连接密码字段、目录选中/服务切换清空、登记请求与执行位置标签；基线图形契约继续通过。
- 实际HTTP验收直接在独立参考平台准备首批5项模型并部署，再通过新增服务连接读取目录、试评分和登记；监控不发起这些模型的训练作业、不下载权重。HBM登记模型已发布并确认在线API评分，容器重建后凭据引用和在线评分恢复有效。其余4项登记模型可在选择列表中使用，未自动覆盖原在线指针。
- 验证服务地址是已知同机http://model-platform:9470，页面与证据均标reference，不标成已核验的远程机器。客户真实平台需提供API/桥接与凭据后再验收。
- 同机HTTP复现脚本为scripts/verify_remote_models.py（相对本模块），只允许显式模拟环境和已知参考服务；实际浏览器点击/视觉尚未验收。

补充：实际完整备份归档已在隔离临时目录恢复通过，44个模型记录含5个外部登记引用；凭据目录未被打包，运行数据未覆盖。本轮历史SQLite约4.8GB，首次旧CLI请求30秒超时，但服务端归档继续并完成；从完成归档执行恢复检查通过。大历史备份的CLI超时/异步化仍属现有运维限制。

实际验收摘要见[HTTP登记证据](../evidence/gpu-v7/remote-models.json)和[汇总](../evidence/gpu-v7/summary.json)。
