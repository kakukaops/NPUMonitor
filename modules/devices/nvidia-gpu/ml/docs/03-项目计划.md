# GPU机器学习监控模块项目计划

更新：2026-11-17。以[需求](01-需求文档.md)与[技术方案](02-技术方案.md)为当前基线。当前运行版本0.5.1，已有两类检测基础、四类DCGM模板及模型平台拆分；本计划描述后续工作，不将文档修订标作功能交付。

## 1. 实施原则与顺序

先把单指标动态基线、多指标联合检测分别做成可解释、可验证的用户能力，再扩充算法。复用现有数据质量、流水线、模型平台和夜莺链路；保留旧制品及历史证据。仅有DCGM时继续推进，不虚构作业或环境数据。

按P0→P1/P2→P3→P4推进，P5在数据到位后执行。P1/P2均完成才可称“两类能力可用”；P5未完成继续标实验/预览。没有实测资源与历史不承诺日历交付时间。

### P1/P2前置：指标适用性

[指标适用性清单](15-GPU指标动态基线适用性与准入.md)已覆盖正式103项去向，本轮仅为需求决策。下一切片实现：A/B选择分级和不可选理由、常量/档位/零值与连续窗口预检、简单参考比较、配置切换提示。首批5字段逐项验收，3个条件字段单列结果；扩展字段和C类转换不自动纳入当前实现。

验收增加U-08/U-09：gauge温度与gauge错误码/门槛/链路宽度有不同准入结果；常量、合法空闲零、正常阶跃和缺口不混淆；C类在转换契约完成前不可训练。上述预检与UI门槛尚未实现，不以本轮103项分类完成代替。

## 3. 双能力验收矩阵

| 验收项 | 用例与预期 | 需求 | 证据要求/现状 |
|---|---|---|---|
| 实际与动态参考 | 原始曲线可独立查看；模型参考随过去窗口变化；预测不使用当前/未来目标 | U-01～03 | 已有因果性单测基础；双能力专项结果待记录 |
| 单指标异常与反例 | 尖峰、持续水平偏移、慢漂移；正常高负载、空闲及水平切换 | U-04、06 | 记录评分分量、异常与未检出/误报，不以注入成功代替泛化 |
| 判定解释 | 分量可追溯到最终分数；构造带内但水平项异常用例并解释 | U-05 | 数值分量已有；API持久化与UI展示需贯通验收 |
| 联合关系 | 各项未越硬阈值但关系破坏；正常相关联动不被简单判坏 | M-01～04 | 同快照PCA/森林回放，显示算法实际支持的证据 |
| 条件与长期模板 | 范围内条件偏离、范围外未知；尖峰与长期窗口区分 | M-05～06 | 沿用profile门槛，四类模板分别记录结果 |
| 无效输入 | 缺一必要字段、sentinel、NaN、陈旧、重复和时间缺口 | U-07、M-07、C-02 | 无伪造参考/正常，缺口不推进确认 |
| 生命周期 | 两类分别训练、影子、发布、回放、回滚；未知保持、有效恢复、重启 | C-03～06、08～10 | 本轮实际API/夜莺事件与模型身份，实验通知仅到既有本地出口 |
| 页面操作 | 两类配置、指标选择、参考图例、解释、空状态、窄屏和错误提示 | C-07 | 浏览器实际点击、图表及错误检查，设施缺失标not_run |
| 真实效果 | 正常历史与已确认异常，评分覆盖、每GPU日事件误报、检出及处理成本 | 需求第5节 | 现场数据与明确标注范围，当前未准入 |

异常点、检测持续段、夜莺事件及通知不是同一统计对象。报告分别记录原始评分延迟、确认延迟与通知延迟，无标签不把异常比例称误报率。

## 4. 范围与维护

首期单张物理GPU，不包含MIG实例、跨GPU同作业比较、有效吞吐/能效或寿命预测。硬规则保持独立。公司平台真实API未提供时只维护适配端口，不宣称已经对接。

新增证据按实际执行版本与时间存入本模块evidence，标记来源、样本范围、通过/失败/not_run及限制。历史v1～v5报告和冻结JSON不改写为本轮结果。监控与模型平台分别备份，容量/HA必须实测，不能因平台拆分视作完成。

本轮仅修改文档，下一实施切片为P1/P2的判定解释与组内证据核对，然后执行P3双能力回归和浏览器验收。
