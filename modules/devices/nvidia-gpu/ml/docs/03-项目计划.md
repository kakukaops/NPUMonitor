## 1. 实施原则

1. 保留现有 GPU 规则、模拟环境和验收记录；新代码、配置、测试、部署与证据进入 `modules/devices/nvidia-gpu/ml/`。
2. 当前独立系统、独立页面；夜莺插件化不进入本期关键路径。
3. 使用既有 GPU 指标研究而非继续扩展通用 QPS/延迟 demo。模型和事件必须按 GPU UUID 与指标语义验证。
4. 先完成“GPU数据 → 模型 → 持久结果 → 夜莺事件”小型闭环，再开发全功能训练管理。
5. 模拟闭环与真实准入分开。没有真实 H100 和历史数据时继续做模拟及契约，不阻塞所有开发，也不越过生产门禁。
6. 生产原始 Prometheus 默认只读；模拟profile和已有实验数据源配置变更按明确范围执行，不能扩散到生产。
7. 硬规则独立运行，ML 不作为关键硬规则的前置确认；未知与硬件恢复分别处理。
8. 所有阶段验收优先使用本地测试通知出口；正式通知、采集变更、设备操作分别按现场授权流程执行。

## 2. 阶段与里程碑

### M0：数据契约、运行边界与开发骨架

目标：锁定GPU输入和实体定义，建立独立模块工程基础，不改变既有规则运行。

交付：字段绑定schema、首期模板清单、模拟/真实来源标记、API与结果协议草案、模块独立Compose和健康检查、旧系统基线快照。

退出条件：

- 可查询既有 Prometheus 的GPU身份和候选指标，或明确记录实际缺失；真实绑定与模拟绑定分开。
- UUID缺失、重复、百分数/ratio、MiB、Counter和枚举的处理有契约测试。
- 实际采样、源保留范围和查询预算可见；训练历史不够时预检失败，不自动回退模拟。
- 旧规则和受管对象集合未被覆盖；模块服务和卷可独立启停。

### M1：GPU检测及夜莺生命周期PoC

目标：在真实Prometheus/夜莺服务链路中完成少量GPU模板，而不是扩展完整算法库。

交付：独立GPU合成输入/回放、温度与功耗时钟关联模板、活动模式模板、因果窗口、模型评分、持久检测状态、专用结果网关、幂等夜莺实验规则和事件关联。

必测场景：可比负载下温度偏离；功耗-时钟关系改变；活动水平持续变化；正常高负载；正常空闲/阶段切换；缺失/NaN/sentinel/重复/源陈旧；Counter重置；推理和网关故障。

退出条件：

- 四个模拟核心用例完成：温度尖峰、缓慢热漂移、功耗时钟关系偏离、活动模式下降；每项有真实数据查询和夜莺触发/恢复证据。
- 高利用率和高显存等正常负载反例不会仅因绝对值高触发硬件故障结论。
- 异常确认后移除输入，同一夜莺活动事件保持；新鲜正常证据满足恢复策略后正确结束，未知不当恢复。
- 网关停机、存储异常、夜莺重启与HTTP错误和空结果的区别通过实测；不满足时M1不能通过，先修正路径或评审外部结果接口。
- 模块无操作真实设备，不覆盖旧硬规则；通知只到本地测试接收器。

### M2：独立Web最小可用版本

目标：用户在独立系统看GPU指标、ML结果、规则事件和覆盖，能够启动预定义检测。

交付：GPU列表、单卡详情、指标曲线/参考带/异常分数、任务与模型状态、数据质量、夜莺事件关联、平台健康、独立访问控制。

退出条件：

- 按cluster/UUID/时间范围查询，原始曲线从当前源读取，派生结果保留在线版本，不用前端伪造历史。
- 已训练/未训练、模拟/真实、正常/异常/未知、已通知/未同步明确区分。
- 可通过内置模板创建任务，无需手写结果PromQL或导入规则。
- 夜莺故障、无GPU数据、无权限和训练未完成有可操作提示，不显示全部绿色。
- 通过桌面和窄屏布局、图表交互、实际点击和浏览器错误检查；若浏览器设施不可用，标为未验收而非通过。

### M3：训练、模型版本与规则自动管理

目标：兑现“可选已有模型，也能自己训练”的能力。

交付：训练预检与快照、异步训练与取消、校准/回放报告、模型库、兼容检查、影子发布与回滚、任务revision和审计、夜莺受管对象对账、自定义Python模型协议示例。

退出条件：

- 内置算法训练和适配的已发布模型复用均可完成用户全流程。
- 历史不足、实体不兼容、特征/单位变更、训练失败时保留旧有效模型；无未来数据泄漏。
- 相同初始化重复执行无重复规则，人工修改冲突可见，原规则库不被覆盖。
- 删除/暂停/替换模型按行政原因处理，不解释为硬件恢复；回滚不丢历史。
- 首个自定义模型遵守协议完成训练/推理测试；HTTP/ONNX等不在本阶段默认承诺范围。

### M4：可靠性、查询预算与可维护性

目标：明确持久化、重启、断网、升级和多组件失败边界。

交付：故障矩阵、备份恢复、schema迁移与回滚、租约与幂等、结果保留、受控权限和审计、容量报告、资源监控与安装说明。

退出条件：

- pending中途重启不伪造连续成立，active重启和长停机按公开契约恢复。
- 重复源样本与重复结果不推进确认或重复创建事件；模型切换不改变稳定事件身份。
- 每源限额、超时、取消、回放和训练隔离可验证；旧规则查询和通知仍在约定预算内。
- 备份能够恢复任务、制品引用、结果水位及告警关联；不通过删除状态卷“修复”故障。
- SQLite若无法满足测得的读写要求，迁移PostgreSQL后重新验收；不宣称未经验证的HA。

### M5：真实H100旁路、效果评估与发布

目标：证明模型在目标工况有效，而不是只证明模拟脚本可检出。

交付：硬件与软件清单、实际字段绑定、真实历史回放、影子运行、人工事件标签、与硬规则的增益对比、最终容量和限制、部署与运维手册。

退出条件：

- H100形态、MIG、UUID和实际采集版本/单位/拓扑已核对；未支持项显示为缺口或不适用。
- 使用真实历史进行按时间回放，给出事件级准确/召回或明确未标注范围、每GPU/组误报预算及发现延迟。
- 模型在约定误报预算下体现增量价值；达不到时保留影子或退役，不以算法复杂度替代收益。
- 完成一次可复现安装及重启/恢复，现有规则和数据源保持原边界。
- 正式通知按现场流程启用，未完成项目列为已知限制或阻断项；真实H100验收不允许写为模拟通过。
