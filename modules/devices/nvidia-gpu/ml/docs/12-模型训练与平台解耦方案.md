# 模型训练与平台解耦方案 v5

更新2026-11-12，交付0.5.0。目标是先把当前训练执行独立，之后替换为公司的训练与部署平台。当前没有公司API文档或凭据，不宣称已完成真实对接，不规定公司原生API必须采用我们的路径。

## 边界

| 部分 | 负责 | 不负责 |
|---|---|---|
| backend/gpu_ml检测系统 | Prometheus查询、字段/源时间质量、场景与检测配置、数据导出、模型引用与在线指针、告警状态、夜莺 | 不执行模型fit、不写新模型joblib、不决定公司训练资源 |
| model_platform独立参考服务 | 异步训练任务、取消、制品与训练数据、校准/集成版本、部署、推理、独立备份 | 不访问Prometheus、夜莺或监控SQLite，不调用监控API |
| model_runtime共享算法库 | 既有算法、数值预处理、校准与判定实现 | 不持有监控数据库或采集连接 |
| model_backends适配层 | 内部训练/部署/评分契约、鉴权、超时、身份与时间校验 | 不假定公司SDK/原生HTTP格式，不上传任意pickle |

model_runtime仍随检测镜像打包，用于历史制品推理和目录兼容；这不是训练仍在监控进程执行。旧gpu_ml.models/pipeline/detectors/dcgm_scenarios仅为兼容导入层，历史pickle类路径保持可解析。完全去除监控镜像的数值依赖，需要先迁移所有历史本地制品，本轮不做破坏性清理。

## 新流程

```text
检测系统准备只读源快照、输入schema与摘要
 → ModelBackend.submit（幂等任务键）
 → 参考模型服务，未来可替换公司平台适配器
 → 异步状态/取消/验证报告/模型引用
 → 检测系统登记模型版本，不保存新权重
 → 人工发布：先平台部署成功，再切换在线指针
 → 在线与回放通过模型API评分
 → 检测系统校验源时间/身份/分数，保存证据并对接夜莺
```

ModelBackend是内部Python端口，参考实现HttpModelBackend。企业平台可以实现同一端口调用原生SDK/API，也可以提供一个HTTP桥接服务映射本项目协议。公司模型服务若仅返回预测值，适配器必须明确特征、预处理、校准和阈值归属后转换成标准评分；不能重复预处理，不能把预测值直接当异常分数。

## 独立运行与存储

Compose新增model-platform，端口仅绑定本机19461，独立模型卷model-platform-data；监控仍为19460、gpu-ml-data。平台接口使用单独内部令牌文件，不显示到页面；用户原有角色直登和权限保持。

训练服务可独立启动，监控停止后仍能对已经导出的数据训练、部署和评分。当前参考服务训练和推理共用容器，只是可替换参考实现，不宣称HA或与企业平台同等资源隔离。检测系统没有依赖平台健康才能启动：旧本地制品仍可工作，新API模型在平台失效时标为未知并保持已有异常，不伪造正常或静默回退旧模型。

## 模型引用与兼容

新模型元数据保存backend_id、platform_id、model_ref及发布后的deployment_ref，以及输入schema、能力、数据摘要与报告。平台身份持久化，卷丢失或错误平台不应重新绑定旧引用；推理响应必须匹配平台/模型/部署身份和输入源时间。返回URL不作为任意调用地址。

旧0.1—0.4本地制品继续加载、检测、回放和回滚。旧制品不自动上传到平台；校准/集成操作先在目标平台重训相应版本，避免网络传送不可信pickle。不同后端模型不直接混合。新模型的后处理、集成和评分都在平台执行，监控只协调版本和指针。

## 故障与恢复

- 提交重试使用同一任务键和输入，重复键不同输入拒绝。
- 监控重启时外部任务进入pending_sync，查询平台状态；不将仍在平台运行的任务当成计算失败。
- 提交超时可能已被平台接收，状态待确认，不盲目创建第二个任务。
- 取消为协作式：排队可取消，运行中在计算检查点生效，不保证立即释放CPU；取消不自动发布模型。
- 部署失败、身份/schema不一致不切换当前模型；无效响应或超时不生成正常证据。
- 后处理/部署等RPC走线程池，不在监控HTTP事件循环中等待公司平台计算。

## 数据与备份

当前参考协议传送最多12000点、16MiB以内的内联JSON，数据按规范JSON摘要校验，不依赖共享模型文件系统。公司平台大数据通常需要对象存储或其数据集服务，具体上传和URI映射放在适配器，当前没有臆造公司数据格式。

监控备份包含配置、结果、数据快照和旧本地制品；新远程模型权重不包含在其中，返回值明确标注remote_model_refs。参考平台有独立备份/空目录恢复，保留平台身份、模型、部署及数据。接入企业平台后按其模型与部署备份机制运维，不能把监控备份当作全系统权重备份。

## 后续公司对接清单

需确认原生训练任务与状态/取消、模型版本与部署、推理请求/响应及批量窗口、认证方式、错误/限流、输入输出schema、预处理/校准归属、数据上传和模型备份。按这些信息实现适配器和契约测试即可，不改DCGM场景、Prometheus与夜莺主流程。公司已有部署的登记/映射以及其原生模型目录，待真实API确定后对接；当前不冒充已经支持未知接口。

## 首次迁移注意

当前只配置一个活动后端。backend_id或服务地址切换不会自动迁移已有API模型引用；保留旧配置或在测试/维护计划中完成新平台重训、验证和切换，不能把旧model_ref发给另一个平台。原0.4本地模型仍可在0.5兼容运行，但应用镜像降级到0.4不能直接读取新API引用，需使用升级前备份。公司原生模型目录和已有部署登记在真实API对接阶段实现。

在线提交评分前及提交结果前都会重查源样本新鲜度，防止公司API延迟将旧正常样本当作恢复证据。回放与训练历史不受在线新鲜度限制，但时间和摘要契约仍必须满足。
