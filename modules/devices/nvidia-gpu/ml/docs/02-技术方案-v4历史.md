# GPU机器学习异常检测技术方案 v4

2026-11-12。版本0.4.0。用户当前只有DCGM指标，因此以[DCGM场景清单](10-DCGM场景清单与数据契约.md)作为功能范围。保留[v3流水线方案](02-技术方案-v3历史.md)的源质量、组件分离、版本、回放和夜莺边界，不继续以算法数量或全指标覆盖作为完成标准。

## 1. 目标与场景

本轮实现：条件热关系偏离、功耗/时钟关系偏离、热行为长期漂移、时钟表现长期漂移。按GPU＋场景批量生成配置，默认只保存证据。目标是发挥条件关系学习、历史基线校正和长期残差统计的作用；不利用没有的作业信息，不实现不可比的多卡排序或产出/能效判断。

机器可读catalog定义必需DCGM字段、目标、条件、方向、时间profile和解释边界。缺少某字段时页面显示缺口，训练/推理不静默删字段或伪造值。场景并不自动代表硬件故障覆盖，具体列表与字段见独立清单。

## 2. 数据路径与兼容

```text
当前Prometheus中的DCGM原始序列
 → 源样本时间、身份、质量校验
 → 场景字段与参考负载/显存时钟模式可比性检查
 → 训练期预处理 → 冻结条件基线
 → 当前条件残差 / 长窗口偏移与斜率
 → 独立校准和阈值 → 持久化证据
 → 默认仅证据；人工授权后夜莺管理事件与通知
```

不增加新的生产指标、不修改旧metric语义和源指纹。模拟仍由既有Prometheus实际采集DCGM字段，不由前端生成历史。本轮只新增两种明确人工恢复的加速注入：thermal_aging、clock_aging，不将其分钟级效果称为真实硬件老化。

新配置是static versioned scene template＋profile，制品保存完整spec；新旧模型制品、快照、回滚兼容。原通用检测入口保留为高级能力，默认引导用户按DCGM场景选择。

## 3. 模型与长窗口

新增dcgm_conditional和dcgm_residual_trend适配器。条件Ridge学习目标和当前/滞后条件的关系，输入标准化及模型只在训练段拟合；不以过去目标值解释持续偏移。残差方向按场景固定，校准与判定沿用v3独立组件。

长期退化是冻结条件基线的持续残差偏移/趋势，不是原始温度直接拟合时间，也不在线重训吸收故障。滑动中位数及截尾斜率抵抗短脉冲；输出量纲明确的残差、残差中位数、斜率/小时、窗口和profile。参考历史和窗口不足、缺口或可比样本不连续时不可评估，不能视作正常。

production关系参考至少1天，长期参考至少7天、趋势窗口6小时；laboratory关系及长期参考至少30分钟、趋势窗口1分钟，仅允许模拟GPU。门槛是工程起点，不代表行业标准或误报预算。长期推理依赖已有Prometheus历史重建窗口，不靠进程内隐藏状态；代价为较长查询，容量尚需现场验证。

## 4. 配置、通知和界面

新增POST /api/gpu-ml/v1/scenario-policies：entities、scenarios、profile，幂等创建，已有实体不自动重建退役配置，单次最多200项。创建不训练、不发布；模型仍需历史训练和自检。

新增POST /api/gpu-ml/v1/tasks/{id}/admission：管理员可在evidence/alert之间切换。允许通知需已发布模型及核验依据、负责人、处置动作。notification_mode影响夜莺受管规则启禁与固定网关；evidence模式不会触发本场景的业务或质量通知，已有其他任务不受影响。手动授权不等于验证了生产检出率。

Web新增“DCGM场景”页：四类说明、字段缺口、配置数量、仅证据模式与当前不支持的场景。训练窗口按profile展示；图表继续展示条件基线、残差参考带及分数，证据区域展示窗口、斜率和限制。用户此前指定的角色自选Demo登录保留；生产关闭Demo登录。

## 5. 验证与准入

正常高负载、单点尖峰、正常负载范围外、时钟模式改变、缺口、关系异常、热/时钟持续漂移分别验证。短脉冲不作为长期漂移证据；不同profile不能混用，production短历史拒绝。端到端必须验证默认不通知、人工允许、实际夜莺事件和恢复、证据/模型版本跨重启保持。

复用60/20/10/10时间切分，校准/比较/最终测试独立构造窗口，不将未标注点当作正常。10%测试异常点自检仍不是生产告警预算。真实数据需以已核查事件、正常条件变化、每GPU日误告警和人工成本与简单基线比较；没有增量价值的场景不进入通知主链。

本轮验收见[实施记录](11-v4实施与验收.md)。真实H100长期效果、环境/变更补充、生产容量/HA、浏览器视觉及告警侧跨任务事件合并仍单列，不因模拟通过而完成。
