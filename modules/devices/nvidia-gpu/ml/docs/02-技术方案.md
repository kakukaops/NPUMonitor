# GPU监控与模型平台技术方案 v5

更新2026-11-12，版本0.5.0。检测范围仍为[DCGM四类场景](10-DCGM场景清单与数据契约.md)，不增加上层作业依赖。本轮将训练、制品、部署与推理执行从监控控制面独立，为后续替换公司的模型平台建立边界。

## 1. 分层架构

```text
监控系统（19460）
  Prometheus → 数据质量/场景 → 不可变训练快照
  → ModelBackend接口 → 独立模型服务 / 未来公司平台适配器
  ← 任务状态、验证报告、模型引用
  发布：部署成功 → 在线模型指针
  推理：模型API → 响应身份/源时间校验 → 持久证据 → 夜莺

独立参考模型服务（19461）
  API → 自有任务队列/SQLite/模型卷
      → model_runtime训练/校准/集成 → 制品/部署 → 评分API
```

监控Engine不再执行fit或写新joblib。参考服务不包含监控Engine、Prometheus Source、Store或夜莺控制代码，不调用监控API；停止监控后仍可训练已导出数据、部署和评分。四类场景、参考profile、默认仅证据及通知授权保持原语义。

## 2. 目录与存储

- backend/gpu_ml：监控控制面、源适配、UI API、模型平台客户端与作业协调。
- model_platform/gpu_ml_platform：独立参考服务、训练执行、Registry、部署、推理、备份恢复。
- model_runtime/gpu_ml_runtime：共享数值模型实现；旧backend模型文件为兼容导入层，保留历史类路径。
- config：输入与场景契约；检测数据卷gpu-ml-data与模型平台卷model-platform-data独立。

监控镜像仍保留共享数值库用于旧制品推理与模型目录校验，不宣称已完全移除数值依赖。新权重只在模型平台保存，监控存backend_id/platform_id/model_ref/deployment_ref及报告和源快照。

## 3. 可替换接口

ModelBackend端口覆盖info、submit、job、cancel、deploy、predict。当前HttpModelBackend调用本地参考服务；未来可实现公司原生SDK适配器，或使用HTTP桥接映射公司API。不假定公司训练、部署和推理采用我们的URL或字段，也不强制传输pickle。

内部契约见[平台接口](13-模型平台接口契约.md)，职责与迁移边界见[独立方案](12-模型训练与平台解耦方案.md)。公司平台已有部署的模型目录和登记方式，待实际API确认后对接；当前完成的是替换入口和参考实现，不是公司真实集成。

## 4. 状态、发布与故障

数据导出和网络作业协调在监控侧，CPU训练在平台侧。幂等任务键绑定输入；提交丢失回执不会盲目创建新任务，状态pending_sync等待核实。监控重启后同步外部作业，不将它们误记为计算已失败。取消为协作式，不保证立即中断CPU，但不自动发布结果。

发布先调用平台部署，回执身份正确后才切换在线指针；失败保留旧指针。线上/回放均通过模型API，平台失效或响应错误标为未知并保持已有异常，不回填正常值，不静默切到旧权重。源时间、原始观测、平台/模型/部署身份、分数和判定均验证。

现有本地制品继续检测、回放、发布与回滚；旧制品的再校准/集成需在目标平台重训，不自动上传任意pickle。新制品后处理和集成由平台执行，不混合不同后端的成员。

## 5. 运维与准入

本地参考平台有独立令牌与数据卷，可单独启动/备份。监控备份不含外部权重，平台权重必须单独备份；恢复保留platform_id，防止丢卷后旧引用悄悄指向新模型。

本轮测试既有检测回归、替换端口桩、真实HTTP训练/部署/推理、取消/幂等、平台停止时状态保持、监控停止时独立训练、两侧备份恢复。最终证据见[v5验收](14-v5实施与验收.md)。公司真实接口、长期硬件效果、生产容量/HA和浏览器视觉仍未准入。
