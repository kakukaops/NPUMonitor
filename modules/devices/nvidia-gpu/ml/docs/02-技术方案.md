# GPU机器学习监控技术方案：两类核心能力

方案修订：2026-11-17；文档版本0.6。后续代码增量为0.6.0，部署与验证状态见[演示记录](16-单指标动态基线演示与验收.md)；文档方案不代表在线验收通过。替代以平台拆分为主线的[v5方案](02-技术方案-v5历史.md)，保留既有平台边界与兼容要求。

关联：[需求](01-需求文档.md)、[实施计划](03-项目计划.md)、[平台边界](12-模型训练与平台解耦方案.md)、[平台协议](13-模型平台接口契约.md)。

## 1. 能力与架构

两条检测路径为单指标动态基线与异常检测、多指标联合异常检测。DCGM条件关系与长期残差漂移属于第二条路径的应用模板，训练/发布平台属于公共支撑。

```text
Prometheus只读查询 → 实体/单位/源时间/数据质量
  ├─ 单指标配置：过去N点 → 当前点预测 → 残差/水平分量
  └─ 多指标配置：当前指标组 → 联合分布/重构分量
                 或 条件历史 → 条件残差/长期漂移分量
  → 独立校准 → 阈值判定 → 持久证据与持续确认 → 夜莺

监控控制面：数据预检、快照、任务/UI、模型引用、状态与事件
独立模型平台：训练、校准、制品、部署、评分API
```

单指标按GPU×指标建配置，多指标按GPU×指标组建配置；条件模板显式记录目标与条件字段。组内字段变更产生新配置/模型schema，不能静默复用旧制品。不支持跨卡共享模型或自动可比组。

## 2. 当前算法与能力边界

| 路径/算法 | 已有实现 | 输出及限制 |
|---|---|---|
| 单指标temporal_mad | LagRidgeDetector，过去N点Ridge预测当前点；默认12点，可设4～60点 | 当前点预测、训练残差固定尺度带、预测残差与水平偏离分量 |
| 单指标level_mad | 相对训练中位数的MAD偏离 | 仅评分，不满足动态参考的完整交付 |
| 多指标joint_pca | 训练期标准化、PCA重构残差及潜空间距离 | 联合分数、重构参考、部分指标贡献；当前点联合检测，无预测区间 |
| 多指标joint_iforest | Isolation Forest组合异常评分 | 仅评分，无参考线/区间/指标归因 |
| 条件dcgm_conditional | 负载当前值和历史均值经标准化后Ridge拟合目标 | 条件基线、方向残差、可比范围及模式检查 |
| 漂移dcgm_residual_trend | 冻结条件基线，残差窗口中位数和截尾斜率 | 持续偏移/斜率证据，独立长历史门槛 |
| ensemble_max | 冻结成员分数/阈值比取最大值 | 仅评分，不合成参考曲线，不承诺优于单模型 |

数值检测器位于`modules/model-services/runtime/gpu_ml_runtime/`，NVIDIA条件和历史适配在`modules/devices/nvidia-gpu/adapters/nvidia_gpu_ml/`，监控编排位于本模块`backend/gpu_ml/`。

### 单指标动态的准确含义

用x[t-N:t]预测x[t]，不使用x[t]或未来值作为该点预测输入。当前参考值随历史窗口改变，但训练参数冻结，online_update=false。不提供未来多步预测、显式日/周周期、自动工况分段或随工况变化的区间宽度。

现有参考带为预测值±3×训练残差稳健尺度，宽度固定，不是概率置信区间，也不是最终告警边界。异常分数还包括相对训练中位数的水平偏离；持续变化可能被短窗预测追随，也可能被水平项检出，需独立评估正常水平切换与慢漂移。

下一实施切片需让UI/API证据清楚关联预测残差分量、水平分量与最终判定，解释“带内异常”；不能仅修改图例后宣称解释验收完成。自适应区间、周期/趋势模型需真实数据比较后另行设计和验收。

### 多指标联合的准确含义

通用PCA/森林学习同一时刻多个指标的组合分布。PCA重构使用当前组内观测，允许这种输入方式，但灰线必须称重构参考，不能称因果预测。PCA的指标贡献不能覆盖所有联合距离成因，森林不输出未经验证的贡献。

条件模型可学习负载与目标关系，其参考也可能使用当前条件，因此称条件基线。长期模板对条件残差进行时间分析；它们不能作为已具备通用多指标时序依赖学习的依据。四类模板及profile门槛见[场景契约](10-DCGM场景清单与数据契约.md)。

### 指标准入与待实现校验

输入选型以[动态基线适用性清单](15-GPU指标动态基线适用性与准入.md)为准，按语义、采集支持、样本可用性、历史可预测性和效果逐层判断；不得仅按gauge/counter决定。A首批5字段、B当前3字段保留现有接口基础，分级选择与统计预检待实现。错误码/状态/配置门槛不直接进入单指标或通用联合模型。

C类累计能耗/限制时长须先实现版本化衍生特征、单位/reset/窗口有效性契约后再注册；当前不新增训练字段。正式规范身份与旧ML身份不一致仍是迁移缺口，新增字段/实体不能绕过。具体字段语义不在ML文档重新定义。

## 3. 公共训练、校准与评价

流水线为StrictPreprocessor → Detector.fit/score_raw → QuantileCalibrator → ThresholdPolicy。预处理支持identity或训练段robust_scale，不插值；参考输出反变换回原单位。窗口不跨源缺口；单指标采样间隔容许偏差为训练cadence的25%。

按源时间切分60%训练、20%校准、10%比较、10%最终测试；各段独立构建窗口。预处理与检测器仅拟合训练段，校准仅使用校准段。最少240个唯一样本只是代码门槛，长窗口可因分段评分不足而失败，不替代历史代表性要求。旧模板的180样本门槛不覆盖新流水线。

现有校准用分量99%分位定标、最大分数99.5%分位作阈值；倍率/校准变更生成新版本。分数非故障概率，参考带与校准阈值分别解释。候选使用同快照同切分，人工审查比较段，最终测试不用于挑选赢家；回放不更改在线状态。

无标签时只报告评分覆盖、异常点比例与持续段，不报告真实误报率或故障准确率。fault、normal_change、collection_problem和unconfirmed分别处理。真实验收增加每GPU日事件数、事件级检出/误报及确认/通知延迟，当前点级报告不冒充完整事件级评估。

## 4. 接口与页面契约

沿用`/api/gpu-ml/v1`下的policies、training-jobs、models、comparisons、ensembles、replays、state和series接口，不在文档修订时变更API版本。

`POST /policies`当前支持univariate/multivariate；前者按卡×指标展开，后者至少两字段、每卡一项。场景使用现有场景配置入口。训练必须绑定不可变输入与源快照，已注册模型兼容检查后才能使用。

在线证据沿用values、expected、bounds、raw_components、calibrated_components、score、threshold、anomaly、contributions及组件版本。capabilities声明reference_kind、reference_band、history_samples、cadence_seconds、metric_contributions及online_update。字段实际可用性须核对平台响应和持久化/API链路，不把数值层已有字段视为UI已经展示。

| 页面内容 | 必须满足的行为 | 当前状态 |
|---|---|---|
| 两类配置入口 | 单指标/多指标分开选择，明确展开数量和训练发布步骤 | 已有入口；产品组织与实际交互待验收 |
| 单指标图表 | 实际曲线＋当前点预测＋参考带＋异常点，标明带宽性质 | 基础已有；判定分量解释待补齐 |
| 联合图表 | 组内原始证据、联合分数；按能力展示重构/条件参考 | 已有按指标切换与分数；完整组内证据交互待验收 |
| 仅评分算法 | 隐藏无能力的参考线/区间，不伪造解释 | 有能力声明和DOM测试；浏览器验收待完成 |
| 缺口与版本 | 缺失/未知不补正常；跨缺口和模型/流水线版本断线 | 已有基础；纳入双能力回归 |

## 5. 模型平台、发布与故障

监控Engine不执行新fit或写新权重，独立模型服务通过ModelBackend端口提供info/submit/job/cancel/deploy/predict。监控保存backend_id/platform_id/model_ref/deployment_ref、报告与源快照；平台保存新权重。未来公司SDK适配或HTTP桥接需映射实际API，当前只有参考实现和端口桩测试。

提交使用输入绑定幂等键，回执不确定进入pending_sync，重启同步外部作业。发布先部署成功并校验身份，再切换在线指针；失败保留旧模型。平台超时/响应错误标未知并保持已有异常，不补正常或静默切模型。

旧本地制品继续推理、回放和回滚，保留历史类路径；修改旧制品需在目标平台重训，不自动上传pickle。监控备份不含远程权重，平台独立备份；platform_id和后端命名空间防止引用误绑定。详细协议与运维沿用12、13、14号文档。

## 6. 持续确认、通知与准入

沿用3个新鲜异常样本确认、3个新鲜正常样本恢复；重复样本不推进，未知不恢复。模型切换保留事件身份，暂停/退役按管理原因处理。规则、ML、输入质量和平台健康分别记录。

四类场景仍默认仅证据，通知需现有管理员授权；通用任务沿用现有通知行为。本次文档不改变运行默认值，也不扩大正式通知范围。

两类能力分别通过因果性/联合关系用例、正常反例、数据质量、版本与生命周期、浏览器交互验收。真实GPU长期效果、生产容量/HA及公司真实接口仍未准入。具体任务与验收见[项目计划](03-项目计划.md)，不能以历史模拟验收替代本轮或真实生产验收。
