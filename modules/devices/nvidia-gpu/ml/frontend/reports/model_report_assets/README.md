# 基于公开数据集的模型选型与评测

> 本仓库包含原 HTML 和 `results/` 下的 CSV。下文的快照、复现脚本与测试属于原始实验目录，需要从实验提供方另外取得。

入口为上一级的 `model_report.html`。报告以一线运维为读者，先介绍部署所用的7种方法，再比较18项单指标的7种方法和多指标的3种方法。HTML数据和图表全部内嵌，可单独离线打开；需要下载CSV或复现时，请保留本文件夹。

报告阅读顺序：模型介绍 → 多指标效果 → 单指标效果 → 报错起始检出 → 结果文件与复现 → 统计口径与五折细节。原第二部分整节移至最后，内容和评价数据均保留。

## 方法公式

报告第一节为7种部署方法补充了核心公式与各方法的符号说明。x表示填补与标准化后的历史统计向量；单指标最多28列、多指标最多504列。公式说明包括逻辑回归的L2惩罚、树叶子的正样本权重2、梯度提升逐轮修正、PCA变换与正常参考中心、孤立森林路径分数、稳健参考尺度下限与指标归因。公式以离线HTML呈现，无需联网加载数学字体或渲染库。公式与当前保存模型的实现对应，没有改动分数、阈值或评价数据。

## 本次采用的口径

- 任务：输入过去5分钟30个10秒端点，判断当前t的节点XID是否非零，不是预测。
- 排除：当前t全部GPU的18项非XID DCGM均无有限数值。0是有效值，部分缺测保留。只检查当前端点，不要求整段历史完整。
- 性能和本次阈值校准均排除上述端点。原444,648个已评分窗口排除228,547个，保留216,101个：50,700个正类、152,976个确认0、12,425个XID未知；15个节点、44个采集区间。
- precision、recall、F1均针对XID异常正类，合并留出节点的TP/FP/FN/TN后计算，不是类别宏平均或节点宏平均。
- 沿用此前指定的运维评价：XID未知但DCGM可用时，报警计FP；未知不修改成已知正常标签，不进入训练正常参考或阈值校准。结果拆分确认0的FP和未知的FP。测试FPR包含运维口径下的未知负类；另外在CSV保留`known_zero_fpr`。
- 缺测端点不再进入性能分母，报告衡量的是可观测条件下的识别能力。被剔除的9,404个XID异常窗口不能算检出，也不能在本口径下继续算FN。部署时仍应提示指标缺失。
- 不包含完全无标签参考实验，也不包含“每折选择一个单指标再拼接”的额外汇总。

## 模型与阈值

来源为原 `DCGM_develop_v1/runs/20261125_detection_v1`。当前报告仅保留部署范围内的645个已训练折模型、129种方案（18×7单指标、3多指标）。原5个节点组不改变，测试组f、验证组(f+1)%5、其余3组训练。本次没有训练模型、改变特征或重选超参数；监督模型原超参数仍是原验证AP选定的结果。正常参考方法的超参数原先固定。

单指标7种方法：L2逻辑回归、梯度提升树、浅层决策树、PCA＋逻辑回归（监督）；PCA T²、孤立森林、稳健参考范围（XID=0正常参考）。多指标只保留浅层决策树（监督）、稳健参考范围和PCA T²（XID=0正常参考）。正常参考方法只采用以训练节点当前XID=0窗口拟合的版本。训练参考是“当前XID=0”，不是要求过去5分钟所有XID为0，也不代表物理上绝对健康。

两套阈值均在过滤后的验证节点重新选定，测试标签不参与：

1. **`fpr_lt_1pct`**：仅使用当前XID确认0的有效验证分数。若有n个零状态窗口，允许的最大误报数k=`(n−1)//100`。将这些分数降序排列，取第k+1大值为阈值，使用严格`score > threshold`报警。这样即使分数并列，也保证本次校准FPR严格小于1%。这一步不读取正类分数；新的测试节点不保证同样的FPR。
2. **`max_f1`**：在XID已知的有效正负验证窗口上最大化正类F1；并列时依次取更高precision、更高阈值。报警条件为`score >= threshold`。正常参考模型的拟合仍不使用正类，但该阈值策略需要正类验证标签，不能称为无故障样本冷启动策略。

监督训练保留全部正类、负类最多降至正类3倍，正类权重2、负类1；验证测试保持原样。无监督参考拟合只用训练XID=0样本，不按正类数量抽样。

## 测试集与原五折的关系

没有另选一份固定测试集，当前指标来自原五折留出测试的合并。19个节点的固定组不变，5轮分别用G1～G5测试，下一组验证，其余3组训练。程序原始折号0～4在报告中显示为第1～5轮。

每个方法有5份折模型；一个节点的窗口只使用将该节点完整留出的模型测试一次。这个节点可以参加另一折模型的训练或验证，但不影响本折留出测试。最后合并各折TP/FP/FN/TN计算指标，不对5个得分简单平均。

排除全部DCGM缺测端点后，每组剩3个有效测试节点，共15个节点。各轮保留窗口依次为69,851、58,455、25,636、28,470、33,689，合计216,101。原分组中另4个节点所有已评分端点均全缺测，仍保留原组归属，但没有窗口进入本次性能分母。具体节点和验证／训练组对应关系见报告“测试集与五折”及`results/test_folds.csv`，19个节点的排除明细见`results/test_nodes.csv`。

本次只收敛展示和导出方法范围，保留方法的数值、窗口、阈值和模型均与上一版一致；没有重新挑选节点。

## 持续报错与起始命中

报告将三种口径写为“明确起始当刻检出 / 45”“首次观测当刻检出 / 59”“报错期间曾检出 / 86”，并给出10:00首次非零、10:03才报警的示意例子：前两项未命中，第三项命中。45包含在59内，59包含在86内；这些数字是分母，不是互斥的故障类别。59=45+14个此前有空白的片段，86=59+27个开头不可评价但之后有可评价端点的片段。


直接复用原始98个XID片段及其真实时间索引，不在排除缺测后重新计算开始时间。

- 明确起始：前一个10秒端点确认0，当前非零，原标记`clear_10s`。共45次、8个节点，45个起始都可评价。
- 首次非零观测时可评价59次：上述45次＋14次此前有缺口的首次观测。不把后者称为精确故障起始。
- 另29个起点全部DCGM缺失，10个起点没有可评分的完整历史，均从起始分母排除。之后恢复数据不能产生新的“起始”。
- 86个片段内部至少有一个保留的正窗口，可另算期间任意检出。该指标会把晚发现也算命中，因此仅作补充。
- 起始命中看该端点的最终报警状态，不要求报警从0切换为1；如果早已在误报并持续到起点，也会命中，需结合FP看。

## 解读限制

每10秒一行、相邻输入重叠，正窗口总数不等于独立故障数。校准FPR目标不保证跨节点保持；真实数据中变化的负载、采集状态和缺测模式都可能影响结果。正常参考分布也可能需要按客户设备和业务逐步重建。模型给出的指标贡献是判断依据，不等于硬件故障因果关系。数据来自故障相关采集区间，precision不能直接外推为生产系统报警可信度。

阈值保留完整浮点精度，重新读取`thresholds.csv`用于报警时请使用`pd.read_csv(..., float_precision="round_trip")`。对阈值四舍五入可能改变恰好位于边界的报警，尤其是分数只有少数取值的决策树。
