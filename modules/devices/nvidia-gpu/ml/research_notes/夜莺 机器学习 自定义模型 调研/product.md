# 夜莺智能告警的产品边界与自定义模型支持

## 夜莺是否有机器学习异常检测能力

### Takeaway
有官方时序智能异常检测能力，但公开产品页将其作为“夜莺智能检测插件”提供，属于商业产品/插件路线；不能据此认为当前开源夜莺镜像自带完整训练与推理服务。

### Cited Findings
- 当前官方智能告警产品页描述：对时序数据实时分析，预测业务曲线趋势；输入指标可反馈训练效果；可与开源夜莺集成，复用告警事件处理。该页同时提供付费选项，因此“可和开源夜莺集成”不等于“插件本身开源”。[官方独立智能检测插件页](https://flashcat.cloud/product/flashcat-aiops-alert/)
- 当前专业版页称在开源夜莺基础上增强，并明确可单独购买智能告警插件，不必据此推断一定要迁移整个平台。[官方专业版页](https://flashcat.cloud/product/flashcat-pro/)
- 专业版历史说明页描述独立部署机器学习训练模块，规则页面选择智能告警，填写指标后可查看训练结果及动态基线，越界交由夜莺告警。该页爬取标示约2.2年前，属于架构与历史交互参考，不能直接当作 v9.3.0 全部功能/兼容矩阵。[历史专业版说明](https://flashcat.cloud/docs/content/flashcat-monitor/n9e-pro/highlights/)
- 官方智能告警介绍文章当前索引明确：智能告警适合周期和趋势指标，不能替代有明确容量/状态边界的静态阈值。[官方智能告警文章](https://flashcat.cloud/blog/n9e-support-anomaly-detection/)

### Inferences
- 产品能力与需求的“规则 + ML”相符，最直接的商业路径是试用独立插件，验证当前 v9.3.0 的实际兼容性；不必为了算法能力先重建告警通知平台。
- 本研究没有安装商业插件，未验证其当前安装包、具体依赖、性能或误报指标。产品页“准确率 >99%”是营销声明，缺少用户数据条件、数据集与评估口径，不能作为项目验收保证。

### Gaps
- 官方公开页面未说明具体采用 Isolation Forest、LSTM、Prophet 或哪些模型，不可擅自推断。
- 未找到公开的当前插件版本与 Nightingale 9.3.0 兼容表；需用实际发行包/试用核对。

## 是否能直接上传或注册自己的异常检测模型

### Takeaway
未找到可靠官方公开材料证明可以直接上传 sklearn/PyTorch/ONNX 模型、注册时序算法 SDK，或把自有推理 HTTP endpoint 注册为商业插件内部模型。因此结论应为“自定义检测模型原生扩展能力尚未证实”，不能断言“已支持”，也不能断言“绝对不能”。

### Cited Findings
- 官方产品页介绍内置智能检测、算法大版本升级和算法优化支持，没有给出客户自带模型的接口契约。[智能检测插件页](https://flashcat.cloud/product/flashcat-aiops-alert/)
- 官方文章 FAQ 说明已有自研监控平台可通过智能异常检测模块 API 创建检测任务、查询结果，然后走已有事件处理流程。此项是**外部系统调用厂商算法服务**，方向与“将用户模型装入夜莺”不同。[官方智能告警文章](https://flashcat.cloud/blog/n9e-support-anomaly-detection/)
- 官方新站首页“模型自选”明确列出 OpenAI 兼容接口、Claude、Gemini、内网模型，所在上下文是 AI Agent、自然语言操作和事件 AI 摘要。这属于大语言模型接入，不能当作时序检测模型插件接口证据。[夜莺当前官方首页](https://n9e.io/zh/)

### Inferences
- 如选择商业插件，应要求厂商以演示/接口文档确认：能否使用用户模型；算法注册与输入输出契约；是否支持训练/推理分离；模型版本、回滚和训练状态接口；是否能对接当前 Prometheus 的认证和租户标签。
- 仅有“算法优化支持”不能推出客户可自行部署任意算法。

### Gaps
- 未找到公开客户模型上传/注册文档、模型 SDK、自定义推理协议、模型打包格式、制品管理接口；商业合同内可能另有定制能力，公开资料不足以确认。
- 官方文章全文工具抓取多次超时；有关任务 API 的证据来自官方页面当前索引正文/FAQ，未拿到接口地址、请求结构或响应格式，不能据此编造 API 路径。

## 哪些相近功能不应混淆

### Takeaway
应区分时序智能检测、LLM 助手、告警后处理与通知扩展：它们发生在不同流程阶段。

### Cited Findings
- 夜莺当前官方首页的 AI Agent 可建规则、生成 PromQL/SQL、诊断未触发原因，事件 Pipeline 可加 AI 摘要，MCP/A2A 用于外部 Agent 调用；此页面并未把这些能力描述为通用时序模型加载平台。[当前官方首页](https://n9e.io/zh/)
- 官方 Script 通知文档明确传入内容是完整告警事件 JSON，通过 stdin 交给外部脚本执行后续操作，这是检测之后的通知/处理能力。[Script 通知媒介](https://flashcat.cloud/docs/content/flashcat-monitor/nightingale-v8/usage/notify-channel/script/)
- 官方告警流程说明为规则调度、查询存储、异常判定、生成事件；事件处理器对已经生成的事件加工，包含标签修改、丢弃和 AI 摘要。[v9 告警流程](https://flashcat.cloud/docs/content/flashcat-monitor/nightingale-v9/usecase/alerting/)

### Inferences
- 当前已有自定义模型 demo 的可控路线仍是让外部模型产生异常分数/基线/健康与新鲜度指标，交给 Prometheus 存储，再由夜莺普通规则触发，利用现有规则生命周期、权限、静默、通知。这是系统集成架构建议，不是声称存在官方模型上传功能。

### Gaps
- 本子任务不做 v9.3.0 源码调用链与运行环境核验，由其他研究子任务负责。当前官网是移动文档，AI 首页描述不能无条件追溯为 v9.3.0 的实际安装能力。
